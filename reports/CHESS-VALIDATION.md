# 3D 체스 구현 및 검증

## 구현 범위

- 컬렉션의 세 번째 플레이 가능한 게임. 첫 화면은 모두 접히며 체스 카드 안에서 썸네일·모드·난이도·색상·테이블에 앉기를 제공합니다.
- 로컬 2인과 입문/쉬움/보통/어려움/전문가 AI. 기본 보통·백, 흑 선택 시 AI 백 선공, 무작위 색상은 새 대국마다 한 번 배정합니다.
- 나무 테두리·녹색/아이보리 8×8 보드·여섯 종류 절차적 3D 기물. 이동/잡기·캐슬링·앙파상·프로모션 표현, 마지막 수·합법 수·체크 표시, 보드 방향/시점 전환.
- 마우스·터치·방향키/Enter/Escape. 모바일 이동 후보가 정해지면 하단 확정 버튼을 표시합니다. 애니메이션 중 입력 차단, 잘못된 버튼·취소 포인터·추가 손가락 처리.
- SAN 기록과 실제 잡힌 기물, 프로모션 네 종류와 선택 취소, 설정·규칙·결과 대화상자.
- 현재 대국의 모드·난이도·색상은 고정하며 대국 설정 변경은 다시 시작부터 적용합니다. 설정 창 진입 시 AI를 취소하고 닫으면 현재 대국 설정으로 재계산합니다.
- 대국·체스 설정은 메모리에서만 관리합니다. 저장·이어하기·새 체스 저장 키·자동 대전 리그·Elo 산정은 없습니다. 기존 오목·리버시 저장 기능은 보존합니다.

## 규칙과 라이선스

chess.js **1.4.0**, BSD-2-Clause를 정확한 버전으로 고정했습니다. 합법 수·체크·캐슬링·앙파상·프로모션·기물 부족과 64비트 Zobrist 해시를 사용합니다. AI 평가·탐색·시간 관리·UI는 자체 구현입니다. 라이선스는 `THIRD_PARTY_NOTICES.md`, `public/chess-license.txt` 및 내보낸 단일 HTML 안에 포함합니다.

chess.js의 `isGameOver`/`isDraw`를 그대로 사용하지 않습니다. 체크메이트를 우선하고 스테일메이트·지원하는 기물 부족·5회 반복·75수는 자동 종료합니다. 3회 반복·50수는 현재 위치 또는 예정한 합법 수를 선언하여 청구합니다. 예정 수는 보드에 실행하지 않습니다. 반복 키에는 차례·캐슬링 권리·합법적인 앙파상 가능성을 반영합니다.

기물 부족은 라이브러리가 지원하는 보수적인 범위이며 모든 임의의 데드 포지션을 증명하지 않습니다. 체스 시계·시간패·온라인 대전은 구현 범위 밖입니다.

## AI

| 단계 | 실제 전략 | 깊이 상한 / 시간 예산 |
| --- | --- | --- |
| 입문 | 기물 가치·간단한 위치 평가, 상위 후보의 제한적인 실수 | 1수 평가 / 100ms |
| 쉬움 | 반복 심화 Negamax/Alpha-Beta, 위치·활동성, 정확한 근접 점수 내 실수 | 2 ply / 300ms |
| 보통 | Alpha-Beta, 합법 수 개수·활동성 평가, 잡기·체크 정렬, Quiescence | 4 ply / 1,000ms |
| 어려움 | 강화된 폰 구조·킹 안전·패스드 폰·비숍 쌍, 킬러/히스토리 정렬, 확장 Quiescence | 6 ply / 2,000ms |
| 전문가 | 반복 심화·Alpha-Beta·Quiescence·전이표·Zobrist 상태 해시 | 10 ply / 3,000ms |

모든 단계는 한 수 메이트를 먼저 찾습니다. 체크 상태의 Quiescence는 깊이 상한에 도달해도 stand-pat 대신 체크 해소 수를 탐색합니다. 모든 단계에 합법적인 제한 시간 대체 수가 있고, 탐색 중단은 마지막 완료 반복을 보존합니다. 전이표는 exact/lower/upper·깊이·메이트 ply 보정과 반수 카운터·전체 반복 횟수 문맥을 포함하며 6,000개 제한을 둡니다.

브라우저는 공통 취소 가능한 Worker 클라이언트를 사용합니다. 직렬화한 초기 FEN·이동 기록·현재 FEN·종료 상태만 전달하며 DOM·Three.js·규칙 엔진 인스턴스를 보내지 않습니다. Worker는 약 8ms 계산 구간마다 약 2ms 실행을 양보합니다. 결과 적용 시 세션 번호·현재 상태·차례를 확인하고 규칙 엔진으로 다시 검증합니다.

## 시간 측정

`npm run chess:measure`는 개막, 전개 후 위치, 룩 종반 **세 개의 개별 포지션**을 기본 시간 예산으로 측정합니다. AI끼리 대전하지 않으며 승률·Elo·난이도별 강약을 판정하지 않습니다. 동기 검색 API의 경과 시간으로 Worker 기동·브라우저 초기 GPU 준비·애니메이션은 포함하지 않습니다.

| 난이도 | 평균 ms | 최대 ms | 세 포지션의 완료 깊이 |
| --- | ---: | ---: | --- |
| 입문 | 19.0 | 27.0 | 휴리스틱 평가 |
| 쉬움 | 253.5 | 300.9 | 1 / 1 / 2 |
| 보통 | 1002.6 | 1003.7 | 2 / 2 / 3 |
| 어려움 | 2001.5 | 2003.0 | 3 / 2 / 4 |
| 전문가 | 3002.5 | 3003.5 | 3 / 2 / 3 |

깊이 상한을 항상 완료하는 것은 아닙니다. 공개 규칙 API와 SAN 생성 비용이 있어 이번 전문가 측정의 완료 깊이는 2~3 ply에 그쳤습니다. 탐색·평가 차이는 구현됐지만 더 높은 난이도의 승률이나 Elo를 보장하지 않습니다. 상세 노드 수·중단 사유: `chess-position-timings.json`.

최종 브라우저 AI 계산 중 1초 동안 PC **58프레임 / 최대 간격 38.1ms**, 모바일 **61프레임 / 16.7ms**를 관측했습니다. 최종 전문가 Worker 탐색 경과 시간은 PC 3002.3ms, 모바일 에뮬레이션 3000.7ms였습니다. 이는 모든 기기·포지션에서 동일한 시간을 보장하지 않습니다.

## 자동 테스트 결과

- `npm test`: **4개 파일, 161개 통과**. 기존 112개와 체스 49개입니다.
- 초기 합법 수 20, perft 400 / 8,902와 Kiwipete 48 / 2,039 등 공개된 기준값을 사용했습니다. 별도의 완전한 체스 엔진으로 독립 검증했다는 뜻은 아닙니다.
- 특수 이동, 자기 체크·핀, 메이트/스테일메이트·기물 부족, 반복 키·현재/예정 수 청구·50/75수, 네 종류 프로모션과 잡기 기록을 검증했습니다.
- 난이도별 합법 수·메이트·체크 해소·프로모션·종료·기한 대체 수·고정 노드/시드 재현, 원본 불변성·전이표 사용/미사용·메이트 거리·반복 이력에 따른 청구 차이, Worker 취소를 검증했습니다.
- 브라우저: **서로 다른 52개 시나리오의 최신 결과 통과**. PC·Pixel 7 에뮬레이션, 신규 체스 8개와 기존 컬렉션·오목·리버시 44개를 포함합니다.
- 최초 전체 시도는 PC GPU 초기 출력 준비 초과 1건과 모바일 체스 레이아웃 오류를 발견한 후 중단했습니다. 당시 25개 통과, 2개 실패, 25개 미완료/중단 상태였습니다. 자원 정리·위치별 UI 캐시·모바일 너비/확정 버튼을 보완한 뒤 체스 8/8과 기존 모바일 22/22를 재실행했습니다. 이후 실제 합법 수 개수를 평가에 추가하고 단위 161개·시간 측정 15포지션 및 PC/모바일 AI 2개도 다시 통과했습니다. 기존 PC 22개와 합쳐 최신 52개를 모두 확인한 것으로, 단일 전체 실행 52/52였다는 뜻은 아닙니다.
- 신규 UI 검증에는 실제 마우스·터치 잡기·방향 전환·AI 백 선공·프레임·오래된 결과 폐기·다음 대국 설정·프로모션 취소/나이트 승격·저장 쓰기 없음·새로고침 초기화·예정 수 무승부 청구가 포함됩니다.
- 상세 실행 이력과 결과: `chess-browser-validation.json`.

## 빌드와 실행 HTML

- `npm run build:html` 성공: TypeScript 검사, Vite 프로덕션 빌드와 단일 HTML 생성 포함.
- `dist/world-table-games.html`: **742,363바이트**, AI Worker **3개** 내장.
- 단일 HTML만 로컬 HTTP에서 제공하고 모든 추가 요청을 차단한 상태에서 오목·리버시·체스 각각 AI 선공 → 사람 이동 → AI 응답까지 3수 진행했습니다.
- 외부 파일 요청 0, 페이지 오류 0, Blob Worker 시작 6회, 서로 다른 내장 Worker 3개, 체스 라이선스 포함 확인.
- 직접 `file://` 열기는 이 클라우드 브라우저의 `ERR_BLOCKED_BY_ADMINISTRATOR` 정책으로 차단돼 검증하지 못했습니다. 로컬 HTTP 검증과 더블클릭 실행을 구분합니다. 상세 결과: `chess-single-html.json`.
- `git diff --check` 통과. 기존 큰 Three.js 번들 경고는 남지만 빌드 오류가 아닙니다.

## 남은 확인과 개선

- 연속 브라우저 실행 중 PC 초기 GPU 준비가 20초를 초과한 사례가 1회 있었습니다. 마지막 재검증에서는 재현되지 않았으나 원인을 확정하거나 모든 초기화 지연을 해결했다고 주장하지 않습니다.
- 실제 iOS/Android 기기·Safari/Firefox·오디오 청감과 장시간 대국의 발열은 미검증입니다.
- 복잡한 위치의 완료 깊이를 높이기 위한 규칙 API 호출·증분 평가·수 정렬 최적화, 전체 반복 문맥으로 인한 전이표 재사용률 개선이 후속 작업입니다.
- 체스 저장과 자동 대전 리그는 요청에 따라 구현하지 않았습니다. 원격 푸시·공개 배포·환경 게시도 수행하지 않았습니다.

실행: `npm install` → `npm run dev`. 배포용 빌드는 `npm run build`, 단일 HTML은 `npm run build:html`, 개별 위치 시간 측정은 `npm run chess:measure`입니다.
