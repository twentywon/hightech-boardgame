# 오목·리버시 오류 수정 검증 — 2026-11-10

## 수정 내용

- 마우스 오른쪽·가운데 버튼이 착수로 처리되던 문제를 수정했습니다. 주 포인터의 왼쪽 버튼만 착수를 확정하며 추가 손가락은 진행 중인 선택을 바꾸지 않습니다.
- 유효하지 않은 보드 위치로 이동하거나 포인터가 취소되면 후보와 확정 버튼을 함께 초기화합니다. 터치 후보는 확정 버튼으로 이동할 때 유지합니다.
- 폐기한 보드의 늦은 입력을 무시하고, 이미 숨겨진 미리보기를 초기화할 때 불필요한 GPU 렌더링을 요청하지 않습니다. 카메라 전환만 끝난 경우에도 상태 갱신 콜백을 호출합니다.
- 오목의 AI 오류·재시도 버튼이 시점 전환이나 포인터 입력 후 사라지던 문제를 수정했습니다.
- 잘못된 Worker 응답과 역직렬화 실패를 명시적으로 거절하고 Worker·타이머를 정리합니다. 오류 후 새 계산을 요청할 수 있습니다.
- 두 게임의 종료 안내가 열려 있는 설정·규칙 창을 덮어쓰지 않도록 수정했습니다. 오목 화면 초기화 실패 시 남은 렌더러도 정리합니다.

## 자동 검증

- `npm test`: 3개 파일, **112개 테스트 통과**. 기존 규칙·AI 테스트와 Worker 응답 오류 5개 사례를 포함합니다.
- Chromium PC / Pixel 7 에뮬레이션: **38개 서로 다른 시나리오의 최신 결과 통과**. 신규 오류 복구 시나리오는 양쪽 플랫폼에서 총 16개입니다.
- 수정 전 신규 PC 재현 테스트 6개 중 5개가 실패했습니다. 최종 전체 실행은 36/38 통과했고, 모바일 오목의 AI 응답·무작위 색상 테스트 두 개는 화면 준비까지 포함한 5초 제한으로 실패했습니다. 테스트 보완 후 관련 두 시나리오를 PC·모바일에서 다시 실행하여 **4/4 통과**했습니다. 단일 전체 실행이 38/38이었다는 뜻은 아닙니다.
- AI 응답 테스트는 Worker 시작을 최대 15초 기다린 뒤 기존 5초 응답 검사를 수행합니다. 최종 재검증의 시작 대기는 PC 7,574ms, 모바일 488ms였습니다. AI 탐색 시간과 초기 화면 준비 시간을 혼동하지 않도록 구분했습니다.
- 무작위 색상 브라우저 테스트는 Three.js 리소스 식별자에도 영향을 주는 전역 `Math.random` 고정을 제거하고, 실제 배정된 색상이 저장·재개 시 유지되는지 검사합니다. 종료 창 테스트는 승리 입력과 설정 열기를 같은 작업에서 발생시켜 렌더링 속도에 따라 충돌 재현 자체가 누락되지 않도록 했습니다.
- Playwright 서버 시작 과정의 `npm run build` (`tsc --noEmit && vite build`) 성공. `git diff --check` 통과.
- 세부 결과: [fixes-browser-validation.json](./fixes-browser-validation.json).
