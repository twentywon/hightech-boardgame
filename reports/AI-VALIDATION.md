# AI 검증 결과

## 범위와 방법

- Node.js v24.22.1, 클라우드 Linux에서 실행했습니다.
- `npm run build` 성공, `npm test` 60개 통과, `AI_BUDGET_SCALE=0.2 npm run ai:evaluate` 2개 평가 테스트 통과.
- 변경한 의존성은 없습니다. 기본 예산 측정과 대전 측정은 별도의 테스트이며, 아래 평균값의 모집단도 다릅니다.

## 흑백 교대 40경기

실행: `AI_BUDGET_SCALE=0.2 AI_ROUNDS=2 AI_MOVE_LIMIT=120 npm run ai:evaluate`. 모든 조합에 서로 다른 개막 2개를 사용하고 각각 흑백을 바꾸었습니다. 난이도마다 흑 8경기·백 8경기입니다.

| 난이도 |  승 |  패 | 미완료 | 승률(전체 경기) | 평균(ms/수) | 최대(ms/수) | 예산 도달 반환 | 불법 수 | 오류 중단 |
| ------ | --: | --: | -----: | --------------: | ----------: | ----------: | -------------: | ------: | --------: |
| 입문   |   0 |  16 |      0 |            0.0% |        0.62 |        6.16 |              0 |       0 |         0 |
| 쉬움   |   9 |   3 |      4 |           56.2% |        0.86 |       69.14 |              1 |       0 |         0 |
| 보통   |   6 |   9 |      1 |           37.5% |       66.91 |      242.10 |              9 |       0 |         0 |
| 어려움 |  13 |   2 |      1 |           81.2% |      258.72 |      488.37 |            216 |       0 |         0 |
| 전문가 |   8 |   6 |      2 |           50.0% |      391.91 |      736.59 |            210 |       0 |         0 |

36경기는 승패로 종료했고, 4경기는 120수 제한에서 중단했습니다. 무승부는 0경기입니다. 시간 예산 도달은 실패나 계산 중단이 아니라 현재 확보한 합법 수를 반환한 사건입니다. 표의 미완료는 각 참가 난이도에 집계되어 실제 중단 경기 수의 두 배로 합산됩니다.

원시 기록: [ai-round-robin.json](ai-round-robin.json). 시간 예산은 각각 20·60·200·400·600ms입니다. OS 스케줄링 및 검사 사이의 작업 때문에 벽시계 시간은 예산을 초과할 수 있습니다.

## 해석과 남은 문제

- 실제로 탐색하지 않는 두 단계와 트리를 탐색하는 세 단계의 계산량·수 선택·완료 깊이가 다릅니다. 전술 테스트는 즉시 승리·장목·강제 방어·복수 위협과 미완료 탐색의 복구를 검증합니다.
- 전이표 사용/미사용의 고정 깊이 결과 일치, 시드+고정 노드 예산 재현성, Worker 종료 후 늦은 응답 폐기를 테스트했습니다.
- 이 소규모 단축 예산 대전에서는 어려움이 가장 높은 승률을 기록했습니다. 보통이 쉬움보다, 전문가가 어려움보다 항상 강하다는 순서는 입증되지 않았습니다. 전문가의 넓은 후보 폭과 위협 연장은 짧은 예산에서 완료 깊이를 줄일 수 있습니다.
- 기본 예산 15개 위치 측정은 계산 시간과 탐색 동작의 표본이며 전체 대전 성능을 입증하지 않습니다. 전체 기본 예산·다양한 개막의 장기 대전과 가중치·후보 폭 보정이 필요합니다.
- 동일 시드라도 벽시계 제한과 머신 부하가 다르면 완료 깊이와 선택 수가 달라질 수 있습니다. 결정적인 검증에는 시간 제한 대신 고정 노드 예산을 사용했습니다.
- 강제 위협 탐색은 연장 수와 후보 폭이 제한되며 모든 강제 승리를 증명하지 않습니다. 전문가도 패배합니다.
- 실제 iOS/Android 기기의 프레임·발열·계산 시간은 미검증입니다. 클라우드 브라우저 검증은 Chromium + Pixel 7 에뮬레이션 + SwiftShader를 사용합니다.

## 브라우저와 정적 빌드 검증

- 최종 프로덕션 빌드를 별도 포트에서 제공한 Playwright PC·Pixel 7 에뮬레이션 **12개 모두 통과**, 실패·스킵·플레이키 판정 0건입니다.
- 마우스·터치 착수, 중복 착수 거부, 저장·재개, 실제 캔버스 이미지로 카메라 전환 확인, 로컬 재시작을 검증했습니다.
- 5단계 선택, 백돌·무작위 배정, 다음 대국 적용 정책, 저장 차단 시 메모리 설정 보존을 확인했습니다.
- 전문가 Worker 계산 중 약 1.6초 동안 PC는 93회(최대 간격 63.2ms), 모바일은 66회(최대 간격 366.7ms) 프레임을 갱신했습니다. 전체 AI 계산 시간과 별개의 UI 응답성 표본입니다. 실제 기기의 프레임 성능을 보장하는 수치는 아닙니다.
- 계산이 시작된 Worker를 실제로 확인한 뒤 재시작·메뉴로 나가고, 이전 수가 새 대국에 적용되지 않는 것을 검증했습니다.
- 초기 테스트에서는 Worker 시작을 고정 시간으로 가정한 검사와 소프트웨어 렌더링 중 초기화·재시작 시간 초과가 있었습니다. Worker 시작 사건과 동기화하고, 변하지 않는 보드의 재렌더링을 생략하며, 장면 종료 시 그림자 맵·WebGL 컨텍스트를 해제했습니다. 초기화·여러 단계 조작을 포함하는 테스트 전체 제한은 60초이며 AI 계산 예산은 변경하지 않았습니다.
- 정적 빌드의 실제 Worker 파일 로딩과 AI 흑 선공을 별도 smoke test로 확인했습니다. 해당 검사에서 브라우저 콘솔 오류는 0건입니다.

기록: [browser-validation.json](browser-validation.json), [production-smoke.json](production-smoke.json).
