# World Table Games

설치 없이 브라우저에서 즐기는 3D 테이블 게임. 15×15 자유룰 오목, 8×8 리버시와 체스를 제공합니다. 독자적인 UI, 프로시저럴 나무 텍스처, Three.js 메시와 Web Audio 합성음을 사용합니다. 서버·계정·외부 에셋은 필요하지 않습니다.

## 실행

Node.js 24 LTS 권장. 검증 환경: Node 24.22.1, npm 11.9.0.

```sh
npm install
npm run dev
npm run build
npm run preview
npm test
```

`package-lock.json`을 커밋했습니다. 재현 가능한 설치에는 `npm ci`를 사용하세요. 클라우드에서 기본 npm 캐시 쓰기 권한이 없다면 `npm ci --cache /tmp/wtg-npm`을 사용합니다.

## 브라우저 테스트

```sh
npx playwright install chromium
npm run test:e2e
# 이미 설치된 Linux Chromium 사용:
CHROMIUM_PATH=/usr/bin/chromium npm run test:e2e
```

테스트는 앱을 빌드한 뒤 별도 포트에서 정적 미리보기 서버를 자동 실행합니다. 기존 개발 서버를 재사용하지 않습니다. 데스크톱과 Pixel 7 에뮬레이션에서 WebGL을 실행하고 마우스/터치 착수, 새로고침 후 재개, 재시작, AI 응답, 설정과 콘솔 오류를 검증합니다. `test-results/`에 메뉴와 게임 스크린샷이 생성됩니다. 클라우드 테스트는 SwiftShader 소프트웨어 렌더링을 사용합니다. 실제 iOS Safari, Android 기기, Firefox의 성능과 오디오 청감은 별도 검증 대상입니다.

## 오목 플레이

- 첫 화면은 모든 게임이 접힌 카드로 시작합니다. **오목 살펴보기**를 누르면 같은 컬렉션 안에서 썸네일과 대국 설정이 펼쳐집니다. 다시 누르면 접히며, 다른 게임을 선택하면 해당 게임만 펼쳐집니다.
- 펼친 카드에서 로컬 2인 또는 컴퓨터 대전을 선택하고 **테이블에 앉기**를 누릅니다. AI 대전 선택 시 5단계 난이도와 플레이어 색상(흑/백/무작위)을 고릅니다. 기본은 보통·흑돌입니다. 백돌을 선택하면 컴퓨터가 선공합니다.
- PC: 교차점에 마우스를 올려 미리보고 클릭합니다.
- 모바일: 교차점을 한 번 누르면 바로 착수합니다. 손가락을 판 위에서 밀면 후보만 고르고, 이때는 착수 확정 버튼으로 둡니다. 잘못 둔 수는 무르기로 되돌립니다.
- 키보드: 게임판에 초점을 둔 뒤 방향키로 후보 이동, Enter로 착수합니다.
- 흑 선공, 5개 이상 연결 시 승리. **삼삼(3-3)** 허용 여부를 새 게임 설정에서 고릅니다(기본 허용). 금지하면 흑·백 모두 열린 삼을 한 번에 두 개 만드는 자리에 둘 수 없고(그 수로 다섯이 되면 예외), 컴퓨터도 그 자리를 피합니다. 승리한 연속 좌표 전체를 강조합니다.
- 시점 전환은 사선/수직, 효과음과 렌더링 해상도는 설정에서 변경합니다.
- **무르기**는 직전 수를 되돌립니다. 컴퓨터 대전에서는 내 차례로 돌아가도록 컴퓨터의 응수까지 함께 되돌리고, 진행 중이던 AI 탐색은 취소합니다. 대국이 끝난 뒤에는 무를 수 없습니다.
- 오목판 가장자리에 A–O·1–15 좌표를 표시합니다. 설정에서 끌 수 있습니다.
- 컴퓨터 대전의 승·패·무를 난이도별로 기기에 기록하고 설정 카드와 결과 창에 표시합니다. 결과 창이 열릴 때 승리·패배 효과음을 재생합니다.
- 대국은 저장하지 않습니다. 새로고침하거나 컬렉션으로 나가면 끝나며, 이어하기는 없습니다(모든 게임 공통). 설정과 컴퓨터 대전 전적만 기기에 남습니다.
- **게임 방법** 창은 모든 게임이 같은 순서로 설명합니다: 기본 규칙 → 그 게임의 용어(표) → 처음이라면 → 조작 → 버튼 → 그 밖에. 틀은 `src/ui/guide.ts`에 있습니다.
- 테이블의 **새 게임**을 누르면 그 게임의 설정 창이 팝업으로 뜹니다(모든 게임 공통, 설정이 없는 게임은 시작 버튼만). 거기서 고른 대전 방식·난이도·색상으로 새로 시작하고, **계속하기**로 닫으면 하던 게임이 그대로 이어집니다. 마지막 난이도·색상 선택은 `wtg.ai.v1`에 저장합니다.

## 블랙잭 플레이

컬렉션에서 **블랙잭 살펴보기**를 누르면 그 줄 안에 썸네일·핵심 규칙·**테이블에 앉기**가 펼쳐집니다. 플레이어 한 명이 딜러와 겨루며 가상 칩만 사용합니다. 저장하지 않으므로 새로고침하면 칩 1,000과 새 슈로 돌아갑니다.

| 항목 | 정책 |
|---|---|
| 칩 | 시작 1,000 / 베팅 10–500, 10 단위 |
| 슈 | 6덱 312장. 남은 카드가 104장 미만이면 다음 라운드 시작 전에 다시 섞음(라운드 도중에는 섞지 않음) |
| 배분 | 플레이어 → 딜러 공개 → 플레이어 → 딜러 비공개 |
| 딜러 | 16 이하 히트, 소프트 17을 포함한 17 이상 스탠드(S17). 공개 카드가 A·10점이면 플레이어 행동 전에 블랙잭 확인 |
| 지급 | 블랙잭 3 : 2, 일반 승리 1 : 1, 푸시는 원금 반환. 양쪽 블랙잭은 푸시, 딜러 블랙잭은 일반 21보다 우선 |
| 더블 다운 | 각 핸드의 처음 두 장에서만. 같은 금액을 더 걸고 한 장만 받음 |
| 스플릿 | 같은 랭크 두 장, 라운드당 한 번. 왼쪽 핸드부터 진행하고 따로 정산. 스플릿 후 21은 일반 21 |
| 스플릿 에이스 | 한 장씩만 받고 자동 스탠드, 더블 불가 |
| 없음 | 보험, 이븐 머니, 서렌더, 사이드 베팅, 재스플릿, 무르기, 난이도 |

- 21이 되면 자동으로 멈춥니다. 모든 핸드가 버스트하면 딜러는 비공개 카드만 공개하고 더 뽑지 않습니다.
- 베팅·더블·스플릿의 칩은 그 순간 차감하고, 라운드가 끝날 때 원금을 포함한 반환액을 한 번 더합니다. 결과 영역에 핸드별 베팅·판정·순이익과 전체 순이익, 돌려받은 칩을 표시합니다.
- 칩이 최소 베팅보다 적으면 **칩 다시 받기**로 칩과 슈를 모두 초기화한 새 세션을 시작합니다.
- 모든 행동은 HTML 버튼입니다(Tab·Enter·Space). 현재 단계·합계·결과는 글자로도 안내하고, 딜러의 비공개 카드는 공개 전까지 화면·접근성 이름·DOM 어디에도 값이 없습니다. 테이블의 3D 캔버스는 장식이며 보조 기술에는 글자 안내를 제공합니다.
- 결과는 대화상자가 아니라 화면 안의 영역에 표시하므로 설정·게임 방법 창과 겹치지 않습니다.

### 블랙잭 구조

- `src/games/blackjack/shoe.ts`: 카드, 6덱 구성, 난수 주입이 가능한 셔플
- `src/games/blackjack/rules.ts`: 점수, 베팅 검증, 배분·히트·스탠드·더블·스플릿, 딜러 진행, 정산. 배분부터 정산까지 각 행동이 한 번의 전이로 끝나므로 같은 라운드를 두 번 배분하거나 정산할 수 없습니다. 거부된 행동은 `null`을 반환하고 입력 상태를 바꾸지 않습니다. 슈가 비정상적으로 바닥나면 그 라운드의 베팅을 전액 돌려줍니다.
- `src/games/blackjack/view.ts`: 절차적 카드·칩·펠트, 상태 차이를 배분·뒤집기·이동으로 그리는 뷰. 규칙을 알지 못하며 비공개 카드의 앞면 정보를 받지 않습니다.
- `src/ui/blackjack.ts`: 베팅·행동 버튼과 글자 안내. 카드가 내려앉을 때까지 입력을 잠가 연속 클릭이 한 번만 처리됩니다.

브라우저 테스트는 게임 코드에 조작 기능을 두지 않고, 페이지의 `crypto.getRandomValues`를 대체하여 실제 셔플이 원하는 순서를 만들도록 합니다(`tests/blackjack-fixtures.ts`).

## 요트 다이스 플레이

컬렉션에서 **요트 다이스 살펴보기**를 누르면 그 줄 안에 썸네일·핵심 규칙·대전 방식·**테이블에 앉기**가 펼쳐집니다. 혼자 하기(점수 도전), 로컬 2인, 컴퓨터 대전(내가 먼저)을 고를 수 있습니다. 저장하지 않으므로 새로고침하면 처음으로 돌아가며, 선택한 방식은 이 페이지를 여는 동안만 기억합니다. 컴퓨터의 난이도 선택과 힌트는 없습니다.

| 항목 | 정책 |
|---|---|
| 차례 | 주사위 5개를 최대 3번 굴림. 첫 굴림은 5개 모두, 이후에는 보관하지 않은 주사위만 |
| 기록 | 한 번이라도 굴린 뒤 열린 칸 하나에 기록. 맞는 족보가 없으면 0점. 한 칸은 한 번만 |
| 진행 | 12라운드(칸 12개). 2인은 번갈아 진행하고 총점이 높은 쪽이 승리, 같으면 무승부 |
| 상단 | 에이스–식스: 해당 눈의 합. 상단 합계 63 이상이면 보너스 35점 |
| 초이스 | 모든 눈의 합 |
| 포카드 | 같은 눈 4개 이상 — 모든 눈의 합 |
| 풀하우스 | 정확히 3개 + 2개 — 모든 눈의 합(다섯 개가 같으면 풀하우스가 아님) |
| 스몰 / 라지 스트레이트 | 연속 4개 15점 / 연속 5개 30점 |
| 요트 | 같은 눈 5개 50점 |
| 없음 | 무르기, 저장·이어하기, 요트 추가 보너스, 3인 이상 |

- 주사위는 옆의 버튼 또는 3D 주사위를 눌러 보관하거나 되돌립니다. 보관한 주사위는 쟁반의 보관 줄로 옮겨집니다.
- 내 차례에는 점수표의 열린 칸이 "지금 기록하면 받는 점수"가 적힌 버튼이 됩니다.
- 주사위를 굴릴 때 녹음된 주사위 소리를 재생합니다.
- 굴림이 끝날 때까지 입력을 잠가 연속 클릭이 한 번만 처리됩니다. 결과는 대화상자가 아니라 화면 안에 표시합니다.

### 요트 다이스의 컴퓨터

컴퓨터는 "보통" 한 단계로 고정되어 있으며(화면에서 고를 수 없습니다) Worker 없이 즉시 계산합니다. 아래 다섯 단계는 엔진과 단위 테스트에만 남아 있습니다. 다섯 주사위의 서로 다른 조합 252가지에 대해 "굴림이 남지 않았을 때의 가치"를 구하고, 남은 굴림 수만큼 거슬러 올라가며 모든 보관 방법의 기댓값을 정확히 계산합니다.

| 단계 | 방식 |
|---|---|
| 입문 | 가장 많은 눈만 남기는 어림 규칙, 가끔 무작위로 남기거나 아무 칸에 기록 |
| 쉬움 | 같은 어림 규칙, 당장 가장 높은 점수에 기록 |
| 보통 | 남은 굴림을 끝까지 계산하되 당장의 점수만 봄 |
| 어려움 | 계산에 더해 각 칸이 나중에 벌 수 있는 평균값을 뺀 가치로 판단 |
| 전문가 | 남은 라운드에 따라 그 평균값을 줄이고 상단 보너스 진도를 반영 |

같은 시드의 혼자 하기 40판 평균은 입문 98, 쉬움 136, 보통 165, 어려움 173, 전문가 174점입니다. 어려움과 전문가는 계산 깊이가 같아 실력 차이가 작습니다. 최적 전략은 아닙니다.

### 요트 다이스 구조

- `src/games/yacht/rules.ts`: 족보 점수, 굴림·보관·기록, 차례와 종료. 거부된 행동은 `null`을 반환하고 입력 상태를 바꾸지 않습니다.
- `src/games/yacht/ai.ts`: 단계별 판단. 결과는 반드시 규칙 함수를 거쳐 적용합니다.
- `src/games/yacht/view.ts`: 절차적 주사위와 쟁반, 굴림·이동 연출, 주사위 클릭.
- `src/ui/yacht.ts`: 버튼·점수표·안내, 컴퓨터 차례 진행.
- `src/core/random.ts`: 블랙잭과 함께 쓰는 난수 공급 함수.

브라우저 테스트는 블랙잭과 같은 방식으로 `crypto.getRandomValues`를 대체해 주사위 눈을 정합니다(`tests/yacht-fixtures.ts`).

## 섯다와 세븐 포커

두 게임은 같은 베팅 엔진(`src/games/cards/betting.ts`), 같은 테이블 뷰(`table-view.ts`), 같은 화면(`src/ui/betting-game.ts`)을 쓰고 카드·족보·진행만 다릅니다. 컴퓨터 좌석은 "보통" 한 단계로 고정되어 있습니다.

- **공개할 카드 고르기**: 처음 받은 카드 가운데 상대에게 보일 한 장을 직접 고릅니다(세 장 섯다, 세븐 포커). 컴퓨터는 좋은 카드를 숨기는 쪽으로 고릅니다.
- **테이블에서 고르기**: 공개할 패·카드나 족보로 쓸 두 장을 고를 때는 오른쪽 버튼 대신 테이블 위의 내 카드를 눌러도 됩니다(두 장은 차례로 누르며, 누른 카드는 위로 조금 올라갑니다). 판 사이에는 테이블의 덱을 눌러 다음 패를 받을 수 있고, 블랙잭에서는 슈를 누르면 딜·히트·다음 라운드가 됩니다.
- **비공개 음영**: 상대에게 보이지 않는 내 카드(세 장 섯다의 숨긴 패, 세븐 포커의 엎은 카드)는 테이블에서 약간 어둡게 보입니다.
- **밀어서 확인**: 마지막에 엎어서 받는 카드(세 장 섯다의 세 번째 패, 세븐 포커의 일곱 번째 카드)는 덮개가 덮인 채 도착합니다. 테이블에서 덮개를 아래로 절반 넘게 밀거나 **확인** 버튼을 누르면 열리고, 그 전에는 그 카드와 그 카드로 만들어지는 족보가 화면·접근성 이름·DOM 어디에도 나오지 않으며 베팅할 수 없습니다.
- **다이**: 포기한 패는 버리지 않고 자기 자리에 엎어서 모아 둡니다(내 패 포함).
- **칩 이동**: 걸 때는 자리에서 판돈으로, 판이 끝나면 판돈에서 이긴 자리로 칩이 날아갑니다. 지급이 끝난 판의 판돈은 0으로 표시합니다.
- 카드가 놓일 때와 칩이 움직일 때 녹음된 효과음을 재생합니다. 나와 컴퓨터 1–3명이 가상 칩 1,000씩으로 시작하며 저장하지 않습니다. 내 칩이 떨어지면 **칩 다시 받기**, 상대의 칩을 모두 따면 **새 세션**으로 다시 시작합니다.

| 공통 | 정책 |
|---|---|
| 기본 판돈 | 판마다 모두 10 |
| 행동 | 체크/콜, 하프(콜 금액 + 콜 뒤 판돈의 절반, 한 베팅 라운드에 세 번까지), 올인, 다이 |
| 올인 | 낸 만큼만 겨루고 나머지는 사이드 팟으로 따로 겨룸. 받아 줄 사람이 없으면 더 올릴 수 없음 |
| 공개 | 상대의 엎어진 카드는 그 상대가 끝까지 남은 대결에서만 공개. 다이한 패는 공개하지 않음 |

**섯다**: 화투 20장(1–10월 두 장씩)을 씁니다. **두 장 섯다**는 두 장을 받고 한 번 베팅합니다. **세 장 섯다**는 두 장을 받아 한 장을 공개하고 베팅한 뒤, 세 번째 패를 엎어서 받아 확인하고 세 장을 든 채 한 번 더 베팅합니다. 베팅이 끝난 맨 마지막에 족보로 쓸 두 장을 고릅니다(혼자 남았으면 고르지 않습니다). 컴퓨터는 기본 강도가 가장 높은 두 장을 고릅니다.

- 족보(높은 순): 38광땡 › 18광땡 › 13광땡 › 장땡 › 9땡 … 1땡 › 알리(1·2) › 독사(1·4) › 구삥(1·9) › 장삥(1·10) › 장사(4·10) › 세륙(4·6) › 갑오 › 8끗 … 1끗 › 망통.
- 땡잡이(3광·7열)는 1–9땡을 이기고 그 밖에는 망통, 암행어사(4열·7열)는 13·18광땡을 이기고 그 밖에는 1끗입니다.
- 구사(4·9)는 상대 최고 패가 알리 이하일 때, 멍텅구리구사(4열·9열)는 9땡 이하일 때 판을 무효로 합니다. 이때는 남아 있던 모두가, 최고 패가 같을 때는 동점자끼리 판돈을 그대로 두고 재경기합니다.
- 특수 족보는 다른 패의 기본 강도를 기준으로 판정합니다.

**세븐 포커**(세븐 카드 스터드): 세 장을 엎어서 받아 그중 한 장을 골라 공개한 뒤, 4–6번째 카드는 펴서, 7번째 카드는 엎어서 받으며 받을 때마다 베팅합니다.

- 보이는 카드가 가장 좋은 좌석이 먼저 베팅합니다(동률이면 앞 좌석).
- 일곱 장 가운데 가장 좋은 다섯 장으로 겨룹니다. A-2-3-4-5는 가장 낮은 스트레이트이고, 무늬에는 순위가 없으며 완전히 같으면 판돈을 나눕니다.
- 모두 올인이면 남은 카드를 한 번에 나눕니다.

**컴퓨터**(화면에서는 보통으로 고정, 아래 단계 비교는 엔진 기준): 이길 확률을 구해(섯다는 남은 카드의 모든 조합, 세븐 포커는 보이지 않는 카드를 120번 무작위로 나눠 추정) 콜 비용과 비교합니다. 단계는 판단의 오차·블러핑·콜 기준이 다릅니다. 좌석을 바꿔 같은 패로 1,500쌍(섯다 3,000쌍)을 붙인 평균 이득은 전문가→입문 +26(섯다 +29), 어려움→보통 +15(+25), 보통→쉬움 +4(0), 전문가→어려움 −1(−3)칩입니다. 즉 전문가·어려움 › 보통·쉬움 › 입문의 세 단계에 가깝고, 올인 판 때문에 한 판의 편차가 큽니다.

## 장기 플레이

컴퓨터 대전에서는 진영(초 선공·한·무작위)과 내 상차림(마상마상·상마상마·마상상마·상마마상)을 고르고, 로컬 2인에서는 초(1P)와 한(2P)이 각자 상차림을 고릅니다. 내가 한이면 판을 뒤집어 보여 줍니다. 저장하지 않습니다.

| 항목 | 정책 |
|---|---|
| 기물 | 궁·사는 궁성 안에서 선을 따라 한 칸. 차는 직선. 포는 포가 아닌 기물 하나를 넘어야 하며 포를 잡을 수 없음. 마는 직선 한 칸 뒤 대각선 한 칸, 상은 대각선 두 칸(길이 막히면 불가). 졸·병은 앞·옆 한 칸 |
| 궁성 대각선 | 차·포·졸·병도 궁성의 대각선 위에서는 그 선을 따라 움직임 |
| 장군·외통 | 자기 궁이 공격받게 두는 수는 둘 수 없음. 장군을 풀 수 없으면 외통으로 패배 |
| 한수쉼 | 장군이 아니면 언제나 가능. 둘 곳이 없어도 쉬면 되므로 스테일메이트는 없음 |
| 빅장 | 두 궁이 사이에 기물 없이 마주 보게 되었을 때 상대가 다음 수에 풀지 않으면 무승부 |
| 반복 | 같은 국면(기물 배치와 차례)이 세 번 나오면 무승부 |
| 점수 판정 | 양쪽이 연달아 쉬거나 200수에 이르면 차 13·포 7·마 5·상 3·사 3·졸·병 2, 한에 1.5 덤으로 승패 결정 |

- 마우스는 기물과 도착점을 차례로 클릭하고, 터치도 기물을 누른 뒤 도착점을 누르면 바로 이동합니다. 키보드는 방향키·Enter·Escape입니다.
- **무르기**는 직전 수(컴퓨터 대전은 내 차례까지), **힌트**는 추천 수를 선택 상태로 제안합니다. 이동 기록 목록은 없습니다.
- 컴퓨터는 Worker에서 알파-베타 탐색을 합니다. 트리 안에서는 자기 궁 안전 검사를 생략하고 궁을 잡는 수를 승리로 평가하며, 한수쉼도 하나의 수로 탐색합니다. 단계는 탐색 깊이(1·2·3·4·시간 제한 내 최대 8)와 잡는 수 추가 탐색이 다릅니다. 보통이 입문을 양쪽 진영에서 이기는 것만 자동으로 확인했습니다.
- 반복수 금지 같은 대회식 세부 규정은 구현하지 않았습니다.

## 윷놀이 플레이

컬렉션에서 **윷놀이 살펴보기**를 누르면 그 줄 안에 썸네일·핵심 규칙·대전 방식·**마당에 앉기**가 펼쳐집니다. 로컬 2인과 컴퓨터 대전(내가 청으로 먼저)을 고를 수 있습니다. 한옥 마당에 멍석을 깔고 두는 장면이며, 툇마루·댓돌·고무신·장독대·돌담은 모두 코드로 만든 것으로 외부 에셋이 없습니다. 저장·무르기·난이도 선택은 없습니다.

- 윷가락 네 개가 각각 반반의 확률로 뒤집힙니다: 도 3/16, 개 6/16, 걸 4/16, 윷 1/16, 모 1/16, 빽도 1/16(붉은 점이 있는 윷가락 하나만 평평한 면).
- 윷·모가 나오면 한 번 더 던지고, 던지기를 모두 마친 뒤 나온 패를 원하는 순서로 원하는 말에 씁니다. 상대 말을 잡으면 한 번 더 던집니다.
- 모서리나 중앙에서 **멈춘** 말만 지름길로 갑니다. 같은 자리의 내 말은 자동으로 업혀 함께 움직입니다.
- 출발점을 지나가야 납니다. 출발점에 딱 멈춘 말은 다음 패로 납니다.
- 빽도는 말판 위의 말을 한 칸 뒤로 옮깁니다(출발점에서는 바깥 19로, 지름길 첫 칸에서는 모서리로). 말판에 말이 없으면 쓰지 못하고 차례가 넘어갑니다.
- 윷가락이 놓인 자리(금색 고리)를 누르면 던집니다. 윷가락은 한 번 길게 날아간 뒤 두 번 낮게 튀며 멈춥니다. **윷 던지기** 버튼도 같은 동작입니다.
- 마당에서 말을 누르면 갈 수 있는 자리에 금색 고리가 뜨고, 고리를 누르면 옮깁니다. 같은 수를 오른쪽 버튼으로도 둘 수 있습니다.
- 컴퓨터는 한 수 앞을 봅니다: 전진 거리, 잡기, 업기, 나기와 다음 던지기에 잡힐 확률을 따집니다.
- `src/games/yut/rules.ts`(규칙), `ai.ts`(컴퓨터), `view.ts`(마당 화면), `src/ui/yut.ts`(조작 화면).

## 헥사 세균전·나인 멘스 모리스·고누

세 게임은 "점 위에 말을 놓고 옮기는 2인 게임"이라는 공통 틀을 씁니다. 로컬 2인과 컴퓨터 대전(내가 먼저)을 고를 수 있고, 무르기가 있으며 저장은 없습니다. 말을 누른 뒤 갈 곳을 누르면 바로 둡니다. 판에 초점을 두면 방향키로 점을 옮겨 다니고 Enter로 고를 수 있습니다.

- **헥사 세균전**: 육각 61칸 가운데 맵이 정한 자리가 막힙니다. 맵은 기본·빈 판·고리·장벽·꽃·징검다리 여섯 가지이며(`MAPS`), 막힌 자리는 들어갈 수 없지만 뛰어넘을 수 있습니다. 각자 모서리의 세균 3개로 시작합니다. 옆 칸으로 가면 **복제**(새 세균이 갈라져 나오는 모션), 두 칸 떨어진 칸으로 가면 **점프**(높이 뛰는 모션)입니다. 도착한 칸에 붙은 상대 세균은 뒤집히며 내 편이 됩니다. 한쪽이 움직일 수 없으면 남은 빈칸을 상대가 차지하고 세균 수로 승부를 가립니다.
- **나인 멘스 모리스**: 점 24개, 말 9개씩. 놓기 → 옮기기 → (말이 셋 남으면) 날기. 셋을 한 줄에 세울 때마다 상대 말 하나를 뗍니다(밀 안의 말은 다른 말이 있는 한 뗄 수 없음). 상대 말이 둘이 되거나 상대가 움직일 수 없으면 이깁니다. 옮기기 단계에서 60수 동안 말을 떼지 못하면 비깁니다.
- **고누**: 윷놀이와 같은 한옥 마당의 흙바닥에 말판을 긋고 돌멩이로 둡니다. 옮길 수 있는 말은 따로 표시하지 않고, 고른 말과 갈 수 있는 자리만 표시합니다. 말판은 다섯 가지입니다.
  - 우물고누: 점 5개, 말 2개씩. 상대를 가두면 이깁니다. 첫 수로 바로 가두는 수는 둘 수 없습니다.
  - 네줄고누: 4×4, 말 4개씩. 내 말을 옮겨 상대 말을 내 말 둘 사이에 끼우면 잡습니다. 상대 말이 하나 남거나 움직일 수 없으면 이깁니다.
  - 호박고누: 집에서 나온 말은 집으로 돌아갈 수 없고 상대 집에도 못 들어갑니다. 상대를 가두면 이깁니다.
  - 자동차고누: 4×4 판의 네 귀퉁이에 둥근 길이 있습니다. 말은 한 칸씩 움직이고, 잡을 때만 둥근 길을 한 번 이상 돌아 빈 길을 달려 처음 만나는 상대 말을 잡습니다. 모두 잡으면 이깁니다.
  - 참고누: 네모 셋을 변의 가운데와 귀퉁이로 이은 판, 말 12개씩. 나인 멘스 모리스의 규칙에 귀퉁이 줄을 더한 것이며 판이 가득 차면 비깁니다.
  - 고누는 지방마다 말판과 규칙이 다릅니다. 여기서는 널리 알려진 방식을 따랐고, 승부가 나지 않는 판은 80수에서 비깁니다.
- 컴퓨터는 세 게임 공통의 알파-베타 탐색이며(`src/games/points/ai.ts`) 난이도가 세 단계입니다: 쉬움(한 수 앞, 열 번에 세 번은 아무 수), 보통(세 수 앞, 0.3초), 어려움(여덟 수 앞까지, 0.9초).
- 구조: `src/games/points/`(공통 형식·탐색·3D 판), `src/games/{hexa,morris,gonu}/`(규칙·말판 모양·문구), `src/ui/point-game.ts`(조작 화면).

## 체커·도츠 앤 박시스·헥스·만칼라·뱀과 사다리

다섯 게임도 헥사 세균전과 같은 공통 틀(`PointGame`, `src/ui/point-game.ts`)을 씁니다. 로컬 2인과 컴퓨터 대전(쉬움·보통·어려움)을 고를 수 있습니다.

- **체커**: 8×8, 말 12개씩. 대각선 앞으로 한 칸, 잡기는 의무이고 한 말로 이어서 뜁니다. 끝줄에 닿으면 왕(두 겹)이 되어 뒤로도 움직입니다. 80수 동안 잡지 못하면 비깁니다.
- **도츠 앤 박시스**: 공책과 색연필. 네모 3×3·5×5·7×7. 두 점 사이를 누르면 색연필 선이 그어지고, 네 번째 변을 그은 사람이 네모를 가져가며 한 번 더 긋습니다.
- **헥스**: 같은 공책에 그린 육각 판(7·9·11). 빨강은 위–아래, 파랑은 왼쪽–오른쪽 변을 이으면 이깁니다. 무승부가 없고, 선수 교환 규칙은 넣지 않았습니다.
- **만칼라**: 사막 나라 시장의 양탄자 위(향신료 바구니·토기·차양). 구멍 6개씩에 돌 4개씩인 칼라 규칙입니다. 마지막 돌이 내 창고에 들어가면 한 번 더, 비어 있던 내 구멍에 떨어지면 맞은편 돌을 가져옵니다. 판은 구멍을 뚫은 두꺼운 널이라 홈이 깊게 보이고, 돌은 앞의 돌이 놓인 뒤에 한 알씩 차례로 놓입니다.
- **뱀과 사다리**: 100칸, 사다리 7개와 뱀 7마리. 6이 나오면 한 번 더 굴리고, 100번 칸에는 딱 맞는 눈이 필요합니다. 운으로만 겨루므로 난이도는 결과에 영향이 없고 무르기는 없습니다.
- 공책 화면은 `src/games/paper/view.ts`가 두 게임에 함께 쓰이며, 판은 캔버스에 색연필 느낌으로 다시 그립니다.

## 스파이더

혼자 하는 카드놀이입니다. 카드 104장(무늬 1·2·4가지 선택)을 열 줄에 깔고(열 줄이 화면 폭을 다 쓰도록 옆 패널을 판 아래로 내리고, 겹친 카드에서도 보이도록 카드 윗부분에 숫자와 무늬를 크게 적었습니다), 같은 무늬로 K부터 A까지 이으면 그 묶음이 판에서 나갑니다. 여덟 묶음을 내보내면 성공입니다. 카드를 끌어서 원하는 줄에 놓습니다(같은 무늬로 이어진 묶음은 함께 움직이고, 놓을 수 없는 곳이면 제자리로 돌아갑니다). **힌트**는 옮겨 볼 만한 카드와 놓을 줄을 노란 테두리로 보여 줍니다. 오른쪽 아래 더미(또는 버튼)로 줄마다 한 장씩 새 카드를 돌립니다. 빈 줄이 있으면 돌릴 수 없습니다. 무르기는 횟수 제한이 없습니다. 카드 그림은 블랙잭·세븐 포커와 같은 덱입니다. `src/games/spider/`, `src/ui/spider.ts`.

## 세계 일주

주사위를 굴려 세계의 도시를 돌며 땅을 사고 건물을 올려 숙박료를 받는 2–4인(나 + 컴퓨터 1–3명) 놀이입니다. 같은 갈래의 기존 상품을 그대로 옮기지 않고, 도시 목록·칸 구성·행운 카드·값을 이 게임을 위해 새로 정했습니다.

- 판은 10×10 크기로 한 변에 열 칸씩 모두 40칸입니다(모서리는 0·10·20·30번): 도시 30곳(칸마다 그 나라 국기), 콜롬비아호, 출발·황금열쇠 4곳·기금 수령·무인도·인류평화기금·우주여행.
- 사기·짓기·우주여행의 갈 곳은 창이 떠서 묻습니다(창을 닫았으면 옆 패널의 버튼으로 다시 고를 수 있습니다).
- 황금열쇠 칸에 서면 판 위의 황금열쇠 카드 더미를 눌러 한 장을 뽑습니다. 카드가 더미에서 떠올라 뒤집힌 뒤 내용이 창으로 나오고, 확인을 누르면 그대로 따릅니다. 카드는 31가지입니다: 상금과 벌금, 다른 칸으로 가기(출발·무인도·우주여행·서울·파리, 한 바퀴 도는 세계 일주 초대권, 앞뒤로 몇 칸), 건물 수리비·재산세·반값 매각, 다른 여행자와 주고받기, 인류평화기금 기부·배당, 그리고 갖고 있다가 저절로 쓰는 **무인도 탈출권**과 **우대권**(숙박료·통행료 한 번 면제). 종류는 이 갈래 놀이에서 흔한 것들을 참고했고 문구와 금액은 따로 지었습니다.
- 주인 없는 도시에 서면 살 수 있고, 내 도시에 다시 서면 건물 말을 하나씩 세웁니다: 집 → 빌딩 → 랜드마크. 세 가지는 서로 다른 모양의 3D 말이며 칸 안쪽 가장자리에 나란히 놓입니다. 땅만 있을 때는 주인의 깃발이 꽂힙니다.
- 남의 도시에 서면 숙박료를 냅니다. 숙박료는 그 도시에 들인 돈(땅값 + 건물값)의 1.5배이며 일의 자리는 버립니다. 돈이 모자라면 싼 도시부터 반값에 팔고, 그래도 모자라면 파산합니다.
- 할 일을 마치면 판 안의 **턴 종료** 버튼으로 차례를 넘깁니다. 그 전까지 내 땅 증서에서 땅을 팔 수 있습니다. 빈 도시에 섰을 때 돈이 모자라도 구매 창이 뜨며, **땅 팔아 마련하기**로 증서를 열어 판 뒤 살 수 있습니다.
- 더블(같은 눈 두 개)이 나오면 판 가운데에 알림이 뜨고 팡파르가 울립니다.
- 같은 눈이 나오면 한 번 더 굴리고, 세 번 이어지면 무인도로 갑니다. 출발을 지나면 월급 200입니다.
- **무인도**는 한 차례 쉽니다. 그 차례에 굴린 주사위가 같은 눈이면 바로 탈출해 그만큼 갑니다(이 더블로는 한 번 더 굴리지 않습니다).
- **우주여행** 칸에 서면 앞으로 어느 칸이든 골라 갑니다. 출발을 지나면 월급을 받고, **콜롬비아호**에 주인이 있으면 그 사람에게 200을 냅니다. 콜롬비아호는 400에 살 수 있고 건물은 못 지으며, 남이 그 칸에 서면 통행료 200을 받습니다.
- **인류평화기금** 칸에 서면 150을 내고, **기금 수령** 칸에 선 사람이 모인 돈을 모두 받습니다.
- 혼자 남거나, 25바퀴가 끝났을 때 "가진 돈 + 쓴 돈의 절반"이 가장 많으면 이깁니다.
- 옆 패널의 여행자를 누르면 그 사람의 **땅 증서**(도시·건물·숙박료·들인 돈)가 창으로 나옵니다. 내 차례에는 내 증서를 들인 돈의 절반에 은행에 팔 수 있습니다.
- 컴퓨터가 뽑은 황금열쇠도 내용이 창으로 잠깐 나왔다가 닫힙니다.
- 효과음: 주사위, 돈을 낼 때의 현금 등록기 소리, 황금열쇠의 반짝이는 소리, 무인도의 파도, 우주여행의 울림. 주사위 외에는 모두 코드로 합성한 소리입니다(`src/engine/sound.ts`).
- 황금열쇠 칸은 노란 바탕에 열쇠, 무인도 칸은 섬, 우주여행 칸은 별과 행성·로켓 그림입니다. 국기와 칸 그림은 단순화해 코드로 그렸습니다(`src/games/tour/flags.ts`, `view.ts`). 외부 이미지가 없습니다.

## 배틀십·사목·돌림 오목·토끼와 사냥개

네 게임도 "점을 고르는 2인 게임" 틀(`PointGame`)에 얹었습니다. 로컬 2인과 컴퓨터 대전(쉬움·보통·어려움), 무르기, 새 게임 팝업, 같은 순서의 게임 방법을 그대로 씁니다. 화면은 `src/games/table/view.ts`의 `TableView`(렌더러·카메라·애니메이션·누른 자리 찾기·해제)를 함께 씁니다.

| 게임 | 규칙 | 배경 |
| --- | --- | --- |
| 배틀십 (Battleship) | 10×10 해도 두 장. 먼저 내 배 5척(5·4·3·3·2칸)을 놓고, 번갈아 한 칸씩 쏘아 먼저 모두 가라앉히면 승리. 컴퓨터 대전만 있음 | 지하 작전실: 콘크리트 벽과 배관, 벽 지도, 갓등 하나, 무전기·전화기 |
| 사목 (Four in a Row) | 7줄 × 6칸의 세운 틀에 원반을 떨어뜨려 넷을 먼저 이으면 승리 | 요양원 탁자: 체크무늬 식탁보, 찻잔, 돋보기안경, 요일 약통, 털실과 바늘, 벽시계와 창 |
| 돌림 오목 (Twist Five) | 6×6 판(3×3 조각 넷)에 구슬을 놓고 조각 하나를 90° 돌림. 다섯을 이으면 승리, 둘 다 다섯이면 무승부 | 책상: 스탠드, 책 더미, 연필꽂이, 공책, 머그잔 |
| 토끼와 사냥개 (Hare and Hounds) | 점 11개. 사냥개 셋은 뒤로 못 가며 토끼를 가두면 승리, 토끼는 모두 지나치면 승리. 사냥개가 10번 잇달아 나아가지 못해도 토끼 승리 | 풀밭 무늬 판, 입체로 빚은 사냥개 세 마리와 토끼 |

- **이름**: 배틀십은 종이와 연필로 하던 때부터 쓰인 놀이 이름이라 그대로 씁니다. 사목과 돌림 오목은 특정 회사의 상품 이름(커넥트 포, 펜타고)을 제목으로 쓰지 않고, 소개 글에서 "흔히 ~로 알려진 놀이 방식"이라고만 밝힙니다. 판 모양과 그림은 모두 따로 만들었습니다.
- **배틀십의 컴퓨터**는 공용 탐색 대신 자기 방식(`aimShot`)으로 쏩니다. 자기가 쏜 결과와 격침된 배만 봅니다. 쉬움은 절반을 아무 데나, 보통은 명중한 칸의 이웃을, 어려움은 남은 배가 놓일 수 있는 경우의 수가 가장 많은 칸을 쏩니다.
- 배틀십은 **배 놓기**로 시작합니다. 긴 배부터 내 해역의 칸을 눌러 놓고, **배 돌리기**로 가로·세로를 바꾸며, **남은 배 무작위로 놓기**로 한꺼번에 놓을 수도 있습니다. 놓일 자리는 노랗게 미리 보이고, 무르기로 방금 놓은 배를 다시 듭니다. 한 화면에서는 서로의 배를 가릴 수 없어 로컬 2인은 없습니다. 배의 위치는 페이지(DOM)에 쓰지 않습니다.
- 좁은 화면에서는 해도 두 장이 위아래로 놓이고(쏠 해도가 위), 배틀십과 사목은 판 높이를 더 씁니다.
- 돌림 오목은 구슬 자리를 누른 뒤 판 옆의 노란 화살표 여덟 개 중 하나를 눌러 돌립니다. 놓은 구슬만으로 다섯이 되면 돌리지 않고 이깁니다.
- 토끼와 사냥개는 새 게임 설정의 **내 말**에서 사냥개와 토끼 중 무엇을 맡을지 고릅니다. 토끼를 고르면 컴퓨터의 사냥개가 먼저 움직입니다.
- 효과음(모두 코드로 합성): 배틀십은 빗나가면 풍덩, 명중하면 폭발. 사목은 원반이 떨어질 때 플라스틱 칩 소리. 토끼와 사냥개는 사냥개가 움직이면 멍멍, 토끼가 움직이면 총총총.

## 숫자야구·알까기·카롬·길막기·도미노·타일 러미

여섯 게임도 같은 틀(`PointGame` + `TableView`)에 얹었습니다. 모두 29종입니다.

| 게임 | 규칙 | 배경 |
| --- | --- | --- |
| 숫자야구 (Number Baseball) | 숫자 3·4자리를 숨기고 번갈아 맞힘. 서로 다른 숫자가 기본이고 **숫자 중복 허용**도 고를 수 있음(어긋난 숫자는 하나씩 짝지어 볼로 셈). 자리까지 맞으면 스트라이크, 숫자만 맞으면 볼. 같은 횟수로 던져 먼저 맞히면 승리 | 학교 교실: 칠판에 분필로 기록과 숫자판을 적음 |
| 알까기 (Alkkagi) | 알을 튕겨 상대 알을 판 밖으로. 바둑알은 3·5·7·10개를 자기 쪽 절반의 격자점에 놓고 시작, 장기알은 장기 첫 자리(16개씩, 세 가지 크기) | 낮은 탁자 위의 두꺼운 판. 장기판은 가운데 접힌 선과 놋쇠 **경첩 두 개가 장애물** |
| 카롬 (Carrom) | 스트라이커를 튕겨 내 말 9개를 네 귀퉁이 구멍에. 넣으면 한 번 더, 여왕은 덮어야 내 것, 스트라이커가 빠지면 반칙 | 꽃무늬를 박아 넣은 흰 대리석 바닥 |
| 길막기 (Wall Race) | 9×9 판에서 말 한 칸 또는 두 칸짜리 벽 하나. 길을 완전히 막는 벽은 금지. 맞은편 끝줄에 먼저 닿으면 승리 | 홈이 파인 나무판 |
| 도미노 (Dominoes) | 28장, 일곱 장씩. 줄 끝과 숫자가 맞는 패를 잇고, 없으면 더미에서 가져옴. 먼저 다 내면 승리 | 어두운 마룻바닥 |
| 타일 러미 (Tile Rummy) | 타일 106개, 14개씩. 같은 숫자 다른 색 3–4개 또는 같은 색 이어지는 숫자 3개 이상으로 묶음. 첫 등록 30점, 판의 묶음을 풀어 다시 짤 수 있음 | 학교 교실 바닥 |

- **이름**: 길막기와 타일 러미는 특정 회사의 상품 이름(쿼리도, 루미큐브)을 제목으로 쓰지 않고 소개 글에서만 밝힙니다. 히트 앤 블로는 분부대로 제목에 쓰고 숫자 야구는 소개 글에 남겼습니다.
- **튕기기**: 알까기와 카롬은 `src/games/flick/physics.ts`의 원반 물리(마찰, 원반끼리의 충돌, 벽·구멍·기둥, 가장자리 밖으로 떨어짐)를 씁니다. 고정된 시간 간격으로 계산해 같은 샷은 언제나 같은 결과가 되며, 규칙과 화면이 같은 코드를 돌립니다. 알을 누른 채 뒤로 당겼다 놓으면 반대쪽으로 나갑니다.
- **컴퓨터**: 알까기와 카롬은 겨냥한 샷들을 머릿속으로 쳐 보고 가장 좋은 것을 고르며, 난이도가 낮을수록 손이 흔들립니다. 숫자 야구는 자기가 받은 판정과 맞는 숫자만 남겨 추리합니다. 도미노와 타일 러미는 자기 패와 판만 봅니다. 타일 러미의 컴퓨터는 보통·어려움에서 판의 묶음을 모두 풀어 자기 타일을 끼워 넣을 수 있는 새 짜임을 찾습니다(`rebuild`, 조커가 든 묶음은 그대로 둠). 알까기의 마찰은 바둑알 12, 장기알 15로 크게 잡았습니다. 바둑알은 세기 16 이상으로 치면 일정 확률(16에서 14%, 한 단계마다 14%씩 늘어 20에서 70%)로 **붕 떠서** 다른 알을 넘어가 떨어집니다(`launch`, 뜬 동안은 아무것도 맞히지 않음). 컴퓨터는 뜨지 않는 세기로만 겨냥합니다.
- **컴퓨터 대전 전용**: 숫자 야구·도미노·타일 러미는 숨긴 것이 있어 한 화면에서 둘이 할 수 없습니다. 이 셋과 알까기·카롬에는 무르기가 없습니다.
- **타일 러미에서 타일 내기**: 내 타일을 여러 개 눌러 고르면(떠오름) 묶음이 될 때 **새 묶음으로 내기** 버튼이 뜹니다. 내 타일 하나를 누르면 붙일 수 있는 판의 묶음 끝에 금색 칸이 뜹니다. 바닥의 타일과 내 타일을 함께 골라 묶음이 되면 **재구성** 버튼이 뜹니다. 배경은 니스 칠한 교실 마룻바닥(길이가 제각각인 널)에 책걸상 다리, 책가방, 실내화가 놓여 있습니다.
- **판 안의 버튼**: 배 돌리기, 가져오기, 차례 마치기 같은 도구 버튼은 모두 게임 화면 안 오른쪽 아래에 뜹니다.
- **게임 방법**: 모든 게임의 설명에서 '조작'과 '그 밖에' 항목을 뺐습니다(`shownGuide`).

## 차이니즈 체커·루도·포켓볼·인디언 포커·테이블 사커

다섯 게임도 같은 틀(`PointGame` + `TableView`)에 얹었습니다. 모두 34종입니다.

| 게임 | 규칙 | 배경 |
| --- | --- | --- |
| 차이니즈 체커 (Chinese Checkers) | 별 모양 판의 구멍 121개, 구슬 10개씩. 한 칸 가거나 구슬을 뛰어넘어 이어 가며, 맞은편 꼭짓점을 먼저 채우면 승리 | 흰 테이블 |
| 루도 (Ludo) | 말 4개씩, 길 52칸과 집으로 가는 길. 6이 나와야 마당에서 나오고 6이면 한 번 더, 상대 말을 잡으면 마당으로 돌려보냄 | 흰 테이블 |
| 포켓볼 (Pocket Ball) | 에이트볼. 먼저 넣은 공으로 단색·줄무늬가 정해지고, 내 공 일곱 개 뒤에 8번을 넣으면 승리. 흰 공이 빠지면 반칙 | 펍 |

- **테이블 사커는 실시간**: 축구대는 `foosball/sim.ts`가 1/120초씩 계산하고(공, 발, 벽, 골), 화면(`view.ts`)이 프레임마다 돌립니다. 규칙(`rules.ts`)에서 수는 "골" 하나뿐이라, 골이 날 때만 `onMove`로 알립니다. 내 막대 네 줄은 함께 움직입니다(마우스·끌기·← →, 누르거나 스페이스로 차기). 컴퓨터(`steer`)는 공이 올 줄의 선수를 공 앞에 세우고 발 앞에 오면 차며, 난이도에 따라 손이 느리고 덜 찹니다. 창이 가려지거나 대화 창이 열려 있으면 멈춥니다.
- **테이블 사커의 막대**는 손이 움직인 거리만큼 그대로 움직입니다(`slide`는 테이블 단위이고 막대마다 자기 끝에서 멈춥니다). 컴퓨터의 손만 속도 제한이 있습니다.
- **차이니즈 체커**: 상대가 자기 집에 구슬을 남겨 두어도, 맞은편 집의 구멍이 모두 차고 그 안에 내 구슬이 있으면 이깁니다. 컴퓨터는 꼭짓점 끝까지의 거리로 판을 재고, 앞으로 가는 수가 적을 때는 옆으로 가는 수도 살펴 집을 끝까지 채웁니다.
- **루도**: 한 칸에 겹친 말은 나란히 작게 세워 모두 보이게 합니다.
- **인디언 포커의 마네킹**은 판마다 탁자에 엎어진 카드를 집어 이마 위로 듭니다(팔은 두 마디 뼈대가 손을 따라갑니다). 한쪽이 걸 칩이 하나도 없게 되면(탁자에 넘어온 판돈도 없을 때) 파산으로 그 자리에서 끝납니다.
- **포켓볼**은 알까기·카롬과 같은 원반 물리(`flick/`)를 씁니다. 당기는 동안 흰 공 뒤로 큐가 보입니다(`FlickView.aimed`). 구멍은 `only`로 특정 공만 받게 할 수 있습니다.
- **인디언 포커**: 컴퓨터(`chooseBet`)는 내 카드만 보고 정하며 자기 카드는 읽지 않습니다. 내 카드의 숫자는 판이 끝나기 전에는 DOM에 쓰이지 않습니다.
- **컴퓨터 대전 전용**: 인디언 포커와 테이블 사커. 이 둘과 루도·포켓볼에는 무르기가 없습니다.
- **펍**: `scenery.ts`의 `pub`(어두운 마루, 벽돌 벽, 네온, 술병 선반, 다트판, 스툴, 맥주잔이 놓인 원탁)을 포켓볼과 테이블 사커가 함께 씁니다.

네 게임은 상대도 컴퓨터도 없는 1인 게임입니다(`PointConfig.solo`). 같은 화면(`src/ui/point-game.ts`)에 얹었고, 옆 패널에는 점수 같은 숫자만 크게 나옵니다. 컬렉션에는 **퍼즐게임** 분류가 생겼습니다. 모두 38종입니다.

| 게임 | 규칙 | 조작 |
| --- | --- | --- |
| 블록 내리기 (Falling Blocks) | 가로 10 × 세로 18칸. 네 칸짜리 블록 일곱 가지가 차례로(일곱 가지가 한 번씩 나온 뒤 다시) 내려오고, 가로줄이 차면 사라집니다. 열 줄마다 레벨이 올라 빨라집니다. 한 줄 100, 두 줄 300, 세 줄 500, 네 줄 800 × 레벨. 끝났을 때 20줄 이상이면 성공 | 좌우로 끌기·톡 눌러 돌리기·내 쪽으로 튕겨 떨어뜨리기, 판 위 버튼, ← → ↑ ↓ 스페이스 |

## 게임 화면의 배치

모든 게임 화면은 `src/ui/chrome.ts`의 `dress`가 같은 방식으로 정돈합니다.

- **판 위(오른쪽 아래)**: 게임을 진행하는 버튼(무르기, 베팅, 히트·스탠드, 선택 취소 등)은 게임 화면 안 오른쪽 아래 구석에 모여 있습니다. 여러 개면 한 줄로 늘어놓지 않고 두 개(블랙잭의 베팅은 세 개)씩 같은 너비로 맞춰 직사각형 묶음을 이룹니다. 판에 이미 겹쳐 있던 버튼(도구 버튼, 베팅 버튼, 턴 종료)도 같은 구석에 섭니다.
- **옆 패널**: 점수·남은 말 같은 상황 정보만 있습니다. 맨 위에 있던 차례 문구는 판 위 문구와 겹쳐서 보이지 않게 했습니다(화면 낭독기를 위해 문서에는 남아 있고, 다시 시도 버튼이 들어갈 때만 보입니다).
- **판 위에는 글자가 없습니다**: 영어 제목과 게임 방식에 대한 작은 글씨를 없앴고, 방식 정보(예: 오목의 `15 × 15 · 삼삼 허용`)는 옆 패널 맨 위에 적습니다.
- **배틀십의 옆 패널**: 양쪽 함대를 그림으로 보여 줍니다. 함선마다 길이만큼의 칸이 한 줄이고, 격침된 배는 흐려지고 이름에 줄이 그어집니다.
- **판 위 왼쪽 위**: 둥근 버튼 두 개 — 뒤로(←, 컬렉션으로)와 설정(⚙). 게임 화면에서는 맨 위의 'World Table Games' 띠와 게임 이름을 보이지 않게 하고, 그만큼 판과 옆 패널을 키웠습니다.
- **판 위 가운데 위**: 차례·안내 문구(`.board-hint`). 오목·리버시·체스·장기도 이제 이 문구를 판 위에 띄웁니다.
- **위쪽 버튼**: 게임 방법, 시점 전환, 새 게임 등은 판 위쪽 오른편 줄에 그대로 있습니다. **새 게임**은 그 게임의 설정 창(모드, 난이도 등)을 띄웁니다.
- **판에서 직접 하는 일은 버튼이 없습니다**: 윷 던지기(윷가락), 섯다·포커의 패 받기(덱, 화살표가 떠 있음), 스파이더의 새 카드 돌리기(더미), 세계 일주의 주사위·황금열쇠, 루도의 주사위, 요트의 주사위 보관, 체스·장기의 이동 확정. 이 버튼들은 화면에는 보이지 않지만 키보드와 화면 낭독기를 위해 남아 있습니다(`.sr-only`).
- **오목·리버시**에는 착수 확정 버튼이 없습니다. 누르면 바로 둡니다.
- **요트 다이스**: 차례의 첫 굴림은 주사위를 눌러도 됩니다. 그 뒤에는 주사위를 눌러 보관하고 **굴리기**로 다시 굴립니다. 옆 패널에는 점수표가 남습니다.
- **섯다·세븐 포커의 카드 순서**: 처음부터 숨긴 패만 줄의 왼쪽에 모입니다(내 것도, 내가 보는 상대 줄도). 마지막에 엎어서 받는 패는 숨긴 패여도 맨 오른쪽에 그대로 둡니다.
- **섯다·세븐 포커의 이름표와 칩**: 족보는 이름과 따로 적습니다(내 것은 이름 옆, 상대 것은 카드의 가운데 쪽). 가운데 판돈은 칩 종류별로 따로 쌓습니다.
- **세븐 포커의 자리**: 판을 넓게 써서 카드를 키웠습니다. 상대가 셋이면 왼쪽·맞은편·오른쪽에 한 명씩 앉고, 덱은 구석으로 갑니다. 족보에는 무엇으로 이루어졌는지도 적습니다(예: `2, 4 투페어`, `K 원페어`, `5, 9 풀하우스`).
- **세계 일주의 숙박료 창**: 사람이 남의 도시나 우주여행 칸에 서면 누구에게 얼마를 냈는지 창으로 알려 줍니다.
- **판에서 고르는 선택에는 버튼이 없습니다**: 섯다·포커에서 카드를 눌러 고르는 선택(공개할 패 등), 밀어서 확인하는 패, 윷놀이에서 말을 눌러 옮기는 선택은 버튼을 보이지 않게 했습니다(`.tap-only`, 키보드용으로는 남아 있음).
- **체스**: 고른 기물을 다시 누르면 선택이 풀립니다(선택 취소 버튼은 없앴습니다). 기물 몸통이 속이 비쳐 보이던 것을 고쳤습니다(양면 재질).
- **배틀십**: 명중하면 한 번 더 쏩니다. 옆 패널에 양쪽의 남은 함선 이름이 나옵니다(위치는 알려 주지 않습니다).
- **컬렉션의 게임 소개**: 글머리표로 된 게임 방법 요약, '지금 플레이 가능' 표시, '이 페이지를 여는 동안만 유지됩니다' 문구를 없애고 짧은 소개만 남겼습니다.
- **윷놀이**: 말이 갈 수 있는 자리는 빨간 고리로 표시합니다. **윷놀이·루도**에서 말을 잡으면 화면 가운데에 "잡았다!"(컴퓨터에게 잡히면 "잡혔다!")가 잠깐 번쩍입니다(`cheer` in `banner.ts`).

## 게임이 끝나면

어느 게임이든 끝나면 결과를 창으로 알려 줍니다(`announce` in `src/ui/chrome.ts`). 옆 패널의 결과 문구를 그대로 읽어 주며, **새 게임** 버튼으로 바로 설정 창을 열 수 있습니다. 오목·리버시·체스는 전부터 쓰던 자기 결과 창을 그대로 씁니다. 섯다·세븐 포커는 세션이 끝났을 때, 블랙잭은 칩이 바닥났을 때 뜹니다.

- **루도**: 길이 꺾이는 칸마다 가는 방향을 가리키는 화살표가 그려져 있습니다.
- **헥사 세균전**: 배경이 우주입니다(별이 뜬 하늘과 멀리 두 개의 행성).
- **테이블 사커**: 축구대가 화면에 가로로 놓입니다. 내 골문이 왼쪽, 상대 골문이 오른쪽이고, 막대는 위아래로 밉니다(마우스·끌기·↑ ↓).

## 결과 창의 그림

게임 결과 창은 이기면 트로피가 빛살과 색종이 속에 떠오르고, 지면 우는 얼굴 위로 비가 내립니다(무승부는 악수). 그림은 Twemoji(CC BY 4.0, `public/emoji-license.txt`)이며 페이지에 그대로 넣어 따로 내려받지 않습니다. 오목·리버시·체스의 결과 창에도 같은 그림이 붙습니다.

- **포켓볼**: 당구대 천의 마찰을 크게 줄여 공이 오래 구르고, 구르는 만큼 공이 돌아 무늬와 번호가 함께 움직입니다.
- **타일 러미**: 타일을 더 키웠습니다(내 패 한 줄에 18개).
- **사목**: 판이 화면을 채우도록 가까이 당겼습니다.
- **세계 일주**: 돈은 모두 '만원' 단위로 적습니다(황금열쇠 문구 포함).
- **인디언 포커**: 판마다 카드를 엎어서 받고, **이마에 얹기**를 눌러야 카드가 올라가며 판이 시작됩니다(그전에는 상대 카드를 알려 주지 않습니다). 컴퓨터가 접으면 카드를 탁자에 내려놓습니다. 컴퓨터는 걸 때 가끔 뜸을 들입니다.

## 흰 공 놓기, 베팅 정하기

- **포켓볼**: 흰 공이 빠지면 다음 사람이 흰 공을 **원하는 곳에 놓고** 칩니다(`State.hand`). 흰 공을 끌어다 놓거나 놓을 자리를 누르면 되고, 치기 전에는 다른 곳을 눌러 몇 번이든 다시 놓을 수 있습니다. 놓은 뒤에 흰 공을 당기면 칩니다. 다른 공 위, 구멍, 천 밖에는 놓이지 않고 가장 가까운 빈자리로 갑니다(`spotFor`). 컴퓨터(보통·어려움)는 공과 구멍을 잇는 줄 뒤에 놓고 칩니다.
- **인디언 포커**: 지금 판돈이 탁자 위 팻말에 적힙니다. 베팅은 **+ 올리기 / − 내리기**로 원하는 만큼 정한 뒤 **결정**을 눌러야 걸립니다(`UP`, `DOWN`, `DECIDE`, `State.wager`). 결정 버튼에는 지금 누르면 어떻게 되는지(체크·콜·베팅 n)가 적혀 있습니다.
- **결과 창**: 그림이 창보다 넓어 생기던 좌우 스크롤바를 없앴습니다.
- **인디언 포커의 판 수**: 탁자 오른쪽 팻말에 열 판 가운데 몇 번째 판인지(예: 3/10)가 적힙니다. 왼쪽 팻말은 판돈입니다.

## 옆 패널, 게임마다

- **옆 패널이 없는 게임**: 사목, 돌림 오목, 토끼와 사냥개, 숫자야구, 길막기, 도미노, 알까기, 카롬, 타일 러미, 차이니즈 체커, 루도, 나인 멘스 모리스, 고누, 체커, 헥스, 뱀과 사다리, 포켓볼. 판이 화면 폭을 다 씁니다(`PointConfig.noPanel`; 패널은 화면 낭독기를 위해 문서에는 남아 있습니다).
- **점수를 크게**: 헥사 세균전, 도츠 앤 박시스, 만칼라는 각자의 점수(칸 수)를 줄 오른쪽에 크게 적습니다(`panel: "big"`). 인디언 포커는 남은 칩 개수만 크게 적습니다.
- **전광판**: 테이블 사커는 축구장 전광판처럼 두 점수를 마주 놓습니다(`panel: "scoreboard"`).
- **배틀십**: 글자 없이 양쪽 함대 그림만 보입니다.
- **세계 일주**: 여행자마다 가진 돈만 오른쪽에 크게 적습니다(쉼·탈출권·우대권이 있을 때만 옆에 덧붙음).
- **윷놀이**: 플레이어마다 말 네 개를 그림으로 보여 줍니다(빈 고리 = 대기, 채운 동그라미 = 말판 위, ✓ = 난 말).
- 패널 맨 위에 있던 한 줄 규칙(게임 방식)은 보이지 않게 했습니다.

## 윷놀이: 넷까지

로컬 모드에서 2–4명이 한 화면에서 번갈아 던집니다(청·홍·녹·황). 시작 전에 이름을 적을 수 있습니다. 누구든 다른 사람의 말이 있는 자리에 서면 그 말들을 잡습니다. 컴퓨터 대전은 전처럼 1 대 1입니다. 포켓볼은 당구대가 화면에 가로로 놓입니다(`TableView.orbit`).

## 세계 일주: 여럿이 한 화면에서

세계 일주는 2–4명이 합니다. 사람은 1–4명까지 앉을 수 있고(한 화면에서 번갈아), 남는 자리는 컴퓨터로 채울 수 있습니다. 시작하기 전에 사람마다 이름을 적습니다(비워 두면 혼자일 때 "나", 여럿일 때 "플레이어 N"). 여럿일 때는 안내 문구가 "○○ 차례"로 이름을 부르고, 사고 짓는 창과 땅 증서 팔기는 차례인 사람의 것으로 뜹니다. 여럿일 때 누가 파산하면 도장은 화면 가운데가 아니라 옆 패널의 그 사람 줄에 찍힙니다.

## 파산 도장

돈이나 칩을 걸고 하는 게임에서 내 돈이 바닥나면 화면 가운데에 **파산** 도장이 크게 찍혔다가 몇 초 뒤 사라집니다(`bankrupt` in `src/ui/banner.ts`, 그림은 `src/assets/bankrupt.webp`로 사용자가 준 것).

- **블랙잭**: 칩이 최소 베팅보다 적어졌을 때.
- **섯다·세븐 포커**: 내 칩을 모두 잃어 세션이 끝났을 때.
- **인디언 포커**: 판이 끝났을 때 걸 칩이 하나도 없으면(비겨서 탁자에 판돈이 남아 있으면 아직 아닙니다). 게임도 그 자리에서 끝납니다.
- **세계 일주**: 내가 파산하면 화면 가운데에, 다른 여행자가 파산하면 옆 패널의 그 여행자 줄에 작은 도장이 남습니다.

## 뒤로 버튼

브라우저나 휴대폰의 뒤로 버튼을 게임 화면에서 누르면 페이지를 떠나지 않고 게임 선택 화면(컬렉션)으로 돌아갑니다. 게임 방법 같은 창이 떠 있으면 먼저 그 창만 닫힙니다. 컬렉션에서 뒤로를 누르면 평소처럼 페이지를 떠납니다. 테이블에 앉을 때 방문 기록을 한 칸 더하는 방식이며(`src/main.ts`), 기록을 건드릴 수 없는 뷰어에서는 브라우저의 원래 동작 그대로입니다.

## 휴대폰은 가로 화면, 항상 밝은 화면

- **가로 화면**: 휴대폰을 세로로 들면 "가로로 돌려 주세요" 안내가 화면을 덮습니다(`#rotate-notice`, CSS 미디어 쿼리로만 켜고 끕니다). 웹 페이지는 스스로 화면을 돌릴 수 없어서, 안내의 **가로 화면으로 전환** 버튼이 전체 화면 + 방향 잠금을 시도하고(안드로이드 크롬 등), 거절되면 휴대폰을 돌려 달라고 알립니다.
- **가로 배치**: 낮고 넓은 화면(`orientation: landscape` 이고 높이 540px 이하)에서는 머리띠를 숨기고 판이 화면 높이를 다 쓰며, 옆 패널은 오른쪽에서 따로 스크롤됩니다. 옆 패널에 상태 문구가 있으므로 판 위의 문구(`.board-hint`)는 숨깁니다.
- **항상 밝은 화면**: `color-scheme: only light`(메타 태그와 `:root`)로 브라우저가 페이지를 어둡게 바꾸지 못하게 했습니다. 다크 모드는 없습니다.
- 브라우저 테스트의 mobile 프로젝트는 Pixel 7 가로입니다.

## 로컬 2인의 시점 회전

체스·장기의 로컬 2인 대전에서는 수를 둘 때마다 테이블이 180도 돌아 차례인 사람이 앞에 오게 합니다. 직전 수가 놓이는 것을 본 뒤(0.35초) 0.7초 동안 판의 세로축을 따라 돕니다(`orbit`, `src/engine/camera.ts`). 도는 동안에는 착수할 수 없고, 무르기를 하면 되돌린 차례의 사람 쪽으로 다시 돕니다. 방향키는 보는 쪽 기준으로 움직입니다. 컴퓨터 대전에서는 돌지 않습니다. 오목·리버시는 돌과 판에 방향이 없어 돌리지 않고, 요트 다이스의 쟁반도 돌리지 않습니다.

## 게임 화면 안의 안내 문구

블랙잭·요트 다이스·섯다·세븐 포커·윷놀이는 옆 패널의 상태 문구("상대에게 공개할 패를 고르세요" 등)를 게임 화면 안에도 띄웁니다(`src/ui/banner.ts`). 넓은 화면에서는 내 자리 아래쪽, 좁은 화면에서는 카드를 가리지 않도록 위쪽에 놓입니다. 보조 기술에는 옆 패널의 문구만 읽히며, 화면 안의 사본은 숨깁니다. 섯다는 아직 두 장을 고르지 않았을 때도 내 패로 만들 수 있는 가장 높은 족보를 내 자리 이름표에 보여 줍니다(세 번째 패를 확인하기 전에는 숨깁니다).

## 게임별 배경

배경은 모두 코드로 만든 3D 장면이며 외부 에셋이 없습니다.

- **오목**: 공원 벤치. 초록 페인트 살대와 철제 틀, 뒤의 등받이, 아래의 잔디와 자갈길, 벤치 위의 낙엽(`parkBench`, `src/engine/scenery.ts`).
- **요트 다이스**: 비행기 좌석. 앞좌석 등받이와 화면, 접이식 테이블과 종이컵, 구름이 보이는 창, 팔걸이와 카펫(`cabin`). 기내가 보이도록 주사위 판을 화면에서 조금 작게 잡았습니다.
- **블랙잭**: 카지노 테이블. 플레이어 쪽이 둥근 펠트, 가죽 팔받침과 놋쇠 선, 딜러의 칩 트레이, 아래의 붉은 카펫(`buildTable`, `src/games/blackjack/view.ts`). 화면 모양(가로·세로)에 맞는 테이블을 따로 둡니다.
- **윷놀이**: 한옥 마당(위 "윷놀이 플레이" 참고).

## 효과음

주사위·카드·칩 소리는 Kenney의 "Casino Audio"(CC0) 가운데 열두 개를 22.05kHz 모노 WAV로 변환해 번들에 내장한 것입니다(`src/engine/sounds/`, 고지는 `public/sound-license.txt`). 외부 요청은 없습니다. 재생할 수 없는 환경에서는 기존 합성음으로 대신합니다. 돌 놓는 소리와 승패 음은 계속 합성음입니다.

## 플랫폼 화면

머리글, 초기 화면, 게임 목록, 대국 설정 패널, 대화상자는 `src/style.css` 끝의 "Platform skin" 구획에서 정의합니다. 먹색 글자와 종이색 바탕에 인주색 강조 하나만 사용하며, 외부 글꼴 없이 시스템 글꼴을 씁니다. 게임 목록은 좌우로 넘기는 타일 레일입니다(터치로 밀기, 양끝의 화살표 버튼, 타일에 초점을 둔 채 ←/→). 타일을 누르면 레일 가운데로 와 살짝 올라가며, 설명·설정·시작 버튼이 레일 아래 패널에 펼쳐집니다. 패널의 꼭지는 고른 타일을 가리킵니다. 타일과 패널의 그림은 각 게임의 실제 테이블 화면(캔버스만, 글자·버튼·옆 패널·선택 표시 제외)을 캡처한 것입니다. `scripts/capture-thumbs.mjs`로 2배 해상도로 다시 찍어 960×720 WebP로 줄여 `src/assets/thumbs/`에 두며, 빌드에 내장됩니다. 3D 테이블과 대국 화면의 구성·색은 이 구획의 영향을 받지 않도록 `.library`, `header`, `dialog`로 범위를 한정했습니다. 대전 방식 라디오는 분할 선택 모양이지만 실제 입력 요소가 알약 전체를 덮어 클릭·키보드·보조 기술 동작은 그대로입니다.

## 화면 크기

대국 화면에서는 머리글과 제목 행을 줄여 남은 높이를 보드에 사용합니다. 카메라 거리는 `src/engine/camera.ts`의 `cameraDistance`가 캔버스 비율·시점·게임별 보드 크기와 기물 높이로 계산하여, 보드 전체가 캡션 여백 안에서 가능한 한 크게 보이도록 맞춥니다. 좁은 화면에서는 나무 테두리의 가까운 모서리가 옆으로 약간 넘칠 수 있지만 착수 영역은 항상 보입니다. 브라우저 테스트도 같은 함수를 사용해 클릭 좌표를 계산합니다.

오목 돌·리버시 원판·합법 수와 승리 표식은 뷰마다 지오메트리와 머티리얼을 하나씩 공유합니다. 메시를 제거해도 공유 자원은 해제하지 않으며 뷰 종료 시 한 번 해제합니다.

- `src/engine/`: 공통 Worker 요청 취소, 씬, Raycaster 입력, 카메라, 애니메이션, 메시 생성·해제, 합성 효과음
- `src/ui/`: 컬렉션, 플레이 UI, 설정·규칙·결과 대화상자
- `tests/`: Vitest 규칙 테스트 및 Playwright 브라우저 테스트

오목 AI는 즉시 승리와 즉시 패배 방어를 먼저 고려합니다. 나머지 수는 난이도별 패턴 평가 또는 탐색으로 선택합니다. 선택한 수는 반드시 규칙 엔진에서 검증합니다. 메시 생성은 `BoardView.makeStone`에 모여 있어 추후 모델 에셋으로 교체할 수 있습니다. 온라인 서버나 불필요한 범용 게임 엔진은 포함하지 않습니다.

## 정적 배포

기본 `base`는 `./`입니다. 특정 하위 경로가 필요하면:

```sh
BASE_PATH=/hightech-boardgame/ npm run build
```

`npm run build:html`은 세 게임의 코드·스타일·AI Worker를 포함하는 단일 `dist/world-table-games.html`도 생성합니다. 별도 에셋 요청 없이 동작하며 chess.js 저작권·라이선스 고지를 HTML 안에도 포함합니다. 디스크에서 직접 연 페이지(`file://`)는 blob URL의 모듈 Worker를 시작하지 못하므로, 내보내기 스크립트는 자체 완결된 Worker를 클래식 Worker로 실행하도록 바꿉니다. 따라서 파일을 더블클릭해도 컴퓨터 대전이 동작합니다. 파일 직접 열기를 차단하는 환경에서는 로컬 HTTP 서버를 사용하세요.

`dist/`를 정적 호스팅에 올립니다. 파일을 직접 여는 대신 HTTP 서버를 사용하세요. GitHub Pages 자동 배포나 저장소 공개 설정은 활성화하지 않았습니다.

패턴 분석은 5목·장목, 열린 4, 막힌 4(갈라진 4 포함), 열린/막힌 3, 열린 2와 교차 위협을 구분합니다. 어려움·전문가는 승리 위협과 강제 방어가 있는 노드를 제한적으로 연장합니다. 전체 보드의 모든 수나 모든 강제 승리 수열을 증명하는 엔진은 아니므로 전문가도 패배할 수 있습니다.

변화가 없는 보드는 다시 그리지 않고 착수·미리보기·카메라·승리 애니메이션 동안 렌더링합니다. 메뉴 복귀와 재시작 시 그림자 맵과 WebGL 컨텍스트를 명시적으로 해제합니다.

초기 보드는 WebGL 동기화 객체를 비동기로 확인하여 GPU 출력 준비 후 AI를 시작합니다. 실제 플레이의 AI 계산은 별도 Web Worker에서 수행합니다. 직렬화 가능한 상태만 전송하고, 돌을 놓을 때 다시 규칙 엔진으로 검증합니다. 재시작·메뉴·새 게임·페이지 종료 시 Worker를 종료하고 세션 번호로 늦은 결과도 폐기합니다. Worker 실패 시 재시도 안내를 표시하며 메인 스레드에서 긴 탐색을 대신 실행하지 않습니다.

두 게임 모두 마우스 왼쪽 버튼만 착수를 확정합니다. 보드 밖으로 이동하거나 포인터 입력이 취소되면 이전 후보를 해제하고, 추가 손가락은 진행 중인 선택을 바꾸지 않습니다. AI 오류·잘못된 Worker 응답은 재시도 안내로 표시하며 시점 전환 후에도 유지됩니다. 대국 종료 시 열려 있는 설정·안내 창을 먼저 닫은 다음 결과를 보여주므로 편집 중인 설정이 사라지지 않습니다. 관련 회귀 테스트는 `tests/e2e/recovery.spec.ts`에 있습니다.

### 평가 재현

```sh
npm test
# 빠른 흑백 교대 40경기(기본 시간 예산의 5%) + 기본 예산 15개 위치 측정
npm run ai:evaluate
# 시간 예산 배율·개막 다양성·수 제한 변경
AI_BUDGET_SCALE=0.2 AI_ROUNDS=2 AI_MOVE_LIMIT=120 npm run ai:evaluate
# 실제 게임과 동일한 예산으로 더 긴 평가(실행 시간이 길어집니다)
AI_BUDGET_SCALE=1 AI_ROUNDS=2 AI_MOVE_LIMIT=225 npm run ai:evaluate
```

`reports/ai-round-robin.json`은 난이도별 승률, 평균·최대 계산 시간, 불법 수, 오류 중단, 시간 예산 도달, 수 제한 중단을 기록합니다. 수 제한 중단은 무승부로 계산하지 않습니다. 각 개막을 흑백 교대로 사용합니다. 벽시계 시간 예산에서는 머신 부하에 따라 탐색 깊이와 결과가 달라집니다. 고정 시드에 `timeMs: Infinity, maxNodes: N`을 사용하면 결정적인 노드 예산으로 재현할 수 있습니다.

`reports/ai-default-budget.json`은 2·8·12수 위치의 기본 시간 예산 측정입니다. `reports/AI-VALIDATION.md`에서 결과와 해석을 확인하세요. 소규모 단축 예산 대전만으로 난이도 순서가 실력 순서임을 확정하지 않습니다.

Playwright는 전문가 계산 중 애니메이션 프레임, Worker 생성, 취소와 새 대국 보호, 난이도·색상 저장, 흑백·무작위 배정, 저장 차단 상황도 검증합니다. Worker 파일을 포함한 `dist/` 전체를 HTTP(S) 서버로 제공해야 합니다.

## 리버시 플레이

컬렉션에서 **리버시 살펴보기**를 누르면 별도 시작 화면으로 이동하지 않고 카드 안에 썸네일·설정·**테이블에 앉기**가 펼쳐집니다. 로컬 2인 또는 컴퓨터 대전, 난이도·흑/백/무작위를 선택합니다. 기본값은 보통·흑돌이며 흑이 선공합니다. 대국 설정 버튼은 컬렉션의 리버시 카드를 펼쳐 다음 대국을 설정하게 합니다. 이어하기는 해당 대국의 고정된 설정을 사용하며 다시 시작은 새 선택을 적용합니다. 홈·컬렉션 복귀와 새로고침 시에는 모든 게임이 다시 접힙니다.

- 8×8, A1은 왼쪽 위입니다. 초기 흑 E4·D5, 백 D4·E5. 초기 흑 합법 수는 D3·C4·F5·E6입니다.
- 상대 돌을 자기 돌 사이에 가둘 수 있는 빈 **칸**에 착수합니다. 가로·세로·대각선 8방향의 모든 해당 돌을 뒤집습니다.
- PC는 클릭, 모바일은 칸을 한 번 누르면 바로 착수, 키보드는 방향키·Enter를 사용합니다. 합법 수 안내를 끄고 켤 수 있습니다.
- 뒤집기 중에는 추가 입력을 받지 않습니다. 원판이 실제로 180도 회전하며 바뀝니다.
- 둘 수 없는 플레이어는 자동 패스합니다. 상대만 둘 수 있으면 상대가 계속 두며, 양쪽 모두 둘 수 없으면 빈 칸이 남아도 종료합니다. 종료 시 실제 돌 개수로 판정하고 빈 칸은 점수에 포함하지 않습니다.
- 리버시의 난이도·색상 선택은 `wtg.reversi.ai.v1`에 오목과 따로 저장합니다. 대국 자체는 저장하지 않습니다.
- 오목↔리버시·새 대국·메뉴 전환은 해당 Worker·타이머·RAF·장면을 해제합니다. 요청 세대 번호와 세션 세대 번호로 오래된 결과를 폐기합니다.

리버시의 **무르기**는 착수를 다시 재생하여 뒤집힌 원판과 자동 패스를 복원합니다. 컴퓨터 대전에서는 패스 때문에 여러 수가 이어졌더라도 내 차례가 될 때까지 되돌립니다. **힌트**는 별도 Worker의 어려움 단계 탐색으로 추천 칸을 금색 고리와 착수 후보로 표시합니다.

안정적인 돌 평가는 **코너에 연결된 연속 가장자리만 계산하는 보수적 하한**입니다. 내부 안정성을 완전히 증명하지 않습니다. 빈 영역의 홀짝 점수 역시 휴리스틱이며 종반 승리의 증명이 아닙니다. X·C 칸 위험은 해당 코너가 비어 있을 때만 부과합니다. 초중반에는 돌 수보다 이동 가능성·프런티어·코너를, 후반에는 돌 수를 더 중요하게 평가합니다.

브라우저의 리버시 Worker는 약 8ms 계산 구간마다 약 2ms 실행을 양보합니다. 같은 탐색 생성기의 보드·전이표·탐색 스택을 유지하므로 처음부터 다시 계산하지 않습니다. 순수 동기 API는 테스트·오프라인 평가에서 같은 생성기를 끝까지 진행합니다.

전문가의 `solved`는 남은 모든 착수 깊이의 탐색을 완료했을 때만 참입니다. 시간 제한으로 중단하면 마지막 완료 깊이의 수를 반환하고 미해결로 남깁니다. 실제 응답에는 Worker 기동·렌더링·짧은 연출 대기가 추가됩니다. 벽시계 예산은 OS 스케줄링·GC 등으로 초과할 수 있으며 보장 시간이 아닙니다. 같은 시드라도 시간 제한에서는 부하에 따라 결과가 달라질 수 있습니다. 재현에는 `timeMs: Infinity, maxNodes: N`을 사용하세요.

```sh
npm test
# 단축 예산 40경기 + 기본 예산 15개 위치 + 8·10빈칸 종반 2개 위치
npm run reversi:evaluate
# 실제 기본 예산에서 장기 평가
REVERSI_BUDGET_SCALE=1 REVERSI_ROUNDS=2 REVERSI_MOVE_LIMIT=60 npm run reversi:evaluate
```

기본 단축 배율은 5%입니다. 조합마다 서로 다른 4수 개막 2개를 흑백 교대로 사용합니다. 승·패·무승부, 계산 시간, 깊이, 강제 패스, 불법 수, 오류, 예산 도달과 중단을 기록합니다. 중단을 무승부로 처리하지 않습니다. 결과는 `reports/reversi-*.json`과 `reports/REVERSI-VALIDATION.md`에 기록합니다. 소표본의 단축 예산 승률을 일반적인 강약 보장으로 해석하지 마세요.

## 체스 플레이

**체스 살펴보기**를 누르면 같은 컬렉션 안에 체스 썸네일과 시작 설정이 펼쳐집니다. 로컬 2인 또는 컴퓨터 대전을 선택한 뒤 **테이블에 앉기**를 누르세요. 기본은 보통·백이며 백이 선공합니다. 흑을 선택하면 컴퓨터가 먼저 둡니다. 무작위 색상은 새 대국 시작 시 한 번 배정합니다.

- PC: 자기 기물 선택 후 도착 칸 클릭. 모바일: 기물·도착 칸 선택 후 이동 확정. 오른쪽·가운데 버튼은 이동하지 않습니다.
- 키보드: 방향키로 커서 이동, Enter로 기물 선택/이동, Escape로 취소합니다. 선택한 기물이 있을 때 방향키는 예정한 도착 칸도 미리 보여줍니다.
- 시점 전환과 보드 방향 전환을 지원합니다. AI 대전은 사람의 색상이 아래에 놓입니다. 카메라·이동 애니메이션 중에는 입력을 제한합니다.
- 캐슬링 때 킹·룩을 함께 이동하고, 앙파상은 실제 폰을 제거합니다. 프로모션은 퀸·룩·비숍·나이트 중 선택하며 Escape로 선택을 취소할 수 있습니다.
- 잡힌 기물을 현재 대국의 메모리에 관리합니다(이동 기록 목록은 없습니다). 프로모션으로 생긴 기물을 초기 기물 수 차이로 잘못 계산하지 않습니다.
- **새 게임** 팝업에서 모드·난이도·색상을 고쳐 새로 시작합니다. **게임 방법**은 기물별 이동, 체크·체크메이트, 캐슬링·앙파상·프로모션의 조건, 무승부 규칙을 항목별로 설명합니다.
- 체스 대국과 설정은 영구 저장하지 않습니다. 홈·컬렉션 복귀로 대국을 끝내며 새로고침 시 체스 설정도 기본값으로 초기화합니다. 저장·이어하기와 자동 대전 평가는 없습니다.

규칙은 **chess.js 1.4.0 (BSD-2-Clause)**의 합법 수·체크·캐슬링·앙파상·프로모션·64비트 Zobrist 상태 해시를 사용합니다. AI는 자체 구현입니다. [THIRD_PARTY_NOTICES.md](./THIRD_PARTY_NOTICES.md)와 `public/chess-license.txt`에 고지를 포함합니다.

### 무승부 정책

체크메이트를 먼저 판정한 뒤 스테일메이트, 지원하는 기물 부족, 5회 반복, 75수 규칙으로 자동 종료합니다. 3회 반복과 50수 규칙은 자동 종료하지 않고 **무승부 청구** 버튼을 제공합니다. 엔진의 반복 키는 차례·캐슬링 권리·합법적인 앙파상 가능성을 포함합니다.

현재 위치에서 청구할 수 없다면 선택한 합법적인 예정 수로 조건이 성립하는지도 검사합니다. 모바일은 도착 칸을 선택한 상태에서, PC는 기물을 선택하고 방향키로 도착 칸을 미리 본 상태에서 청구할 수 있습니다. 예정 수는 실제로 실행하지 않고 선언하여 대국을 끝냅니다.

기물 부족은 chess.js가 지원하는 보수적인 범위입니다. 킹만 남음, 킹과 단일 비숍/나이트 등은 판정하지만 임의의 모든 데드 포지션을 증명하는 기능은 아닙니다. 체스 시계와 시간패는 구현 범위에 포함하지 않습니다.

### 체스 AI

| 난이도 | 전략 | 깊이 상한 / 계산 예산 |
| --- | --- | --- |
| 입문 | 기물 가치·단순 위치 평가, 상위 후보에서 일부 실수 | 1수 평가 / 100ms |
| 쉬움 | 반복 심화 Negamax, 기본 위치·활동성, 정확히 평가된 근접 후보에서 제한적 실수 | 2 ply / 300ms |
| 보통 | Alpha-Beta, 합법 수 개수·활동성, 잡기·체크 정렬, Quiescence | 4 ply / 1,000ms |
| 어려움 | 강화된 폰 구조·패스드 폰·킹 안전·비숍 쌍 평가, 킬러·히스토리 정렬, 확장 Quiescence | 6 ply / 2,000ms |
| 전문가 | 반복 심화·Alpha-Beta·Quiescence·Zobrist 전이표·중반/종반 평가 | 10 ply / 3,000ms |

모든 단계는 한 수 메이트를 먼저 찾습니다. 체크 상태의 Quiescence 노드는 stand-pat으로 종료하지 않고 체크 해소 수를 탐색합니다. 반복·50수 청구는 선택 가능한 무승부로, 5회 반복·75수는 자동 무승부로 탐색합니다. 전이표는 깊이·경계·메이트 거리 보정과 함께 반수 카운터 및 전체 반복 횟수 문맥을 포함합니다.

깊이는 상한이며 실제 완료 깊이를 보장하지 않습니다. chess.js 공개 API의 합법 수와 SAN 생성 비용이 있어 복잡한 포지션에서는 제한 시간에 1 ply만 완료할 수도 있습니다. 시간 제한에는 마지막 완료 반복의 최선 수를 반환하고, 그 전에는 합법적인 대체 수를 반환합니다. 전문가도 패배할 수 있으며 Elo나 난이도별 승률을 주장하지 않습니다.

브라우저는 Worker에서 약 8ms 구간마다 실행을 양보합니다. 메뉴·재시작·설정·페이지 종료는 계산을 취소하고 세션 번호로 늦은 결과를 폐기합니다. 대표 시간 측정은 대국 리그가 아닌 세 포지션의 단일 착수 탐색입니다.

```sh
npm test
npm run chess:measure
CHROMIUM_PATH=/usr/bin/chromium npm run test:e2e
npm run build:html
```

시간 측정은 `reports/chess-position-timings.json`에 기록합니다. 초기 화면 준비, Worker 기동, 실제 탐색, 애니메이션 대기를 구분해서 해석해야 합니다.

체스의 **무르기**는 시작 위치에서 남은 수를 다시 재생하여 잡힌 기물·캐슬링 권리·반복 기록을 복원합니다. 컴퓨터 대전에서는 컴퓨터의 응수까지 함께 되돌립니다. **힌트**는 추천 수를 기물과 도착 칸의 선택 상태로 제안하며 이동은 직접 확정합니다. 프로모션 추천은 확정 시 기물을 선택합니다.

## 코드 검토와 최적화

오목은 기존 돌 메시를 재사용하고 변경된 수만 생성합니다. 대국 초기화나 교체 시에는 사용하지 않는 메시를 해제합니다. 세 게임의 결과 창은 페이지 복귀 시 표시 대기 상태를 복원하며, 이미 확인한 결과를 다시 띄우지 않습니다. 체스는 합법 수의 SAN 체크메이트 정보를 재사용하고, 이동 기록·잡힌 기물 DOM은 실제 상태가 바뀔 때 갱신합니다.

검토 범위와 검증 결과는 [코드 검토 보고서](reports/CODE-REVIEW.md), 체스 단일 포지션의 전후 측정은 [측정 JSON](reports/CODE-REVIEW-performance.json)에 기록합니다. 이 측정은 AI 간 대전이나 실력 평가가 아닙니다.

게임 화면은 바깥 여백과 상태 패널 간격을 줄이고 보드 표시 영역을 확대했습니다. 세 게임의 카메라 거리를 기존의 90%로 조정했으며, 모바일에서도 화면 폭에 맞춰 보드를 표시합니다.

보드 높이는 상단 메뉴와 줄바꿈된 게임 버튼의 실제 높이를 제외한 화면 공간으로 제한됩니다. 창 크기와 모바일 방향이 바뀌면 다시 계산하며, 상태 패널 높이가 보드 영역을 늘리지 않도록 분리했습니다.
